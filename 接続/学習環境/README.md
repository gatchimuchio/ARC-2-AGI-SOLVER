# 専用HDS学習機械の公開教材環境

## Ownerの目的

ARCリポジトリの専用HDS学習機械を経験で育て、ARCコンペで満点を出す汎用ラーニングマシンを開発する。

本変更はその開発の第一段階である。環境の稼働、局所試験の合格、原理数の増加を最終目的の達成としない。専用機械の正本は `HDS/学習系統/v0.4.2/hds学習系統`。外部ミニドラをこの機械の代替・必須条件にしない。

## 最小循環

公開ARC形式 `{"train": [{"input": ..., "output": ...}], "test": [...]}` を教師が読む。

1. 教師は入力だけを機械へ渡す。予測要求に課題ID・filename・答え・採点結果はない
2. 予測と状態署名を固定してから教師が公開正解と比較する
3. trainだけ、予測後に正解を「観測出力」として機械へ渡す
4. 既存HDSが経験保持、懐疑、関係候補生成、反証、検証、採用・隔離を行う
5. 未教示のtestへ適用し、教師が採点する。testの入力・正解・採点は学習状態へ入らない
6. 次課題へ同一HDSを継続し、過去の原理・経験・反例を保持する

trainの同じ例への再試行と、testへの未教示適用を別計数にする。testの学習曲線照会は何度行っても完全非学習であり、教師結果から候補や予算を選ばない。

これは信頼されたPython部品間の値・状態契約であり、悪意あるPythonコードを隔離するOSセキュリティsandboxではない。

## 実行

Python 3.11以上、標準ライブラリのみ。GPU、外部モデルAPI、ネットワーク、競技提出は実験中に使わない。

正規checkoutでは、既存submodule `入力/公式ソース/ARC-AGI-2` を固定commit `f3283f727488ad98fe575ea6a5ac981e4a188e49` へ展開しておく。データの再配布や正解表をproductionへ追加しない。

```sh
python3 道具/リポジトリ環境監査.py
python3 -m unittest discover -s 検証/学習環境 -v
python3 -m 接続.学習環境.実験 \
  --教材 入力/公式ソース/ARC-AGI-2/data/training \
  --固定表 検証/学習環境/教材固定_予算適合.json \
  --問題数 6 --最大セル数 36 --最大学習経験 8 \
  --出力 出力/予算適合_継続
```

最初の無選別8課題も `--固定表 検証/学習環境/教材固定.json --問題数 8` で再現できる。

教材は固定表のSHA256を検証してから実行する。追加の小規模教材は、公開training先頭100課題を順に走査し、train 3〜8例、全train/test格子36セル以下という事前条件で選んだ6課題。解けた問題だけを選んだものではない。100件中94件の除外理由を固定表に保持する。

出力には集計、課題別教師履歴、学習曲線、最終HDS保存物と各段階の監査参照を含む。機械実装署名を固定し、学習前後の途中で実装が変われば停止する。保存物は別実装へ無言移行しない。時刻を除いた論理状態署名と、時刻を含むHDS原保存物は区別する。

## 内部学習と開発変更

### 内部学習

固定コード下でのみ、HDSの経験・原理・適用範囲・反証・失敗情報が変わる。教材内の色や解法をdotが読み取って候補追加する処理はない。格子Adapterは行数・列数・座標・色を列挙するだけ。

### 今回の開発変更

- 教師、予測契約、ARC入出力射影、非学習評価、保存・復元、比較実験を接続
- 既存HDS推論に領域非依存の暫定「定値関係」を追加。値自体は3件以上の異なる観測から得る。既存の反証・隔離・採用処理を使う
- 前課題で採用された同値関係と補助定値を、観測形状条件と現在課題の再検証つきで転用

定値を推論候補に含めること、初期支持3・転用再検証2という閾値、座標ベースの観測射影は開発者が選んだ一般的な帰納バイアスである。これらのコード変更を機械自身の学習に算入しない。再現試験は旧HDSと変更後を分ける。

## 課題間転用の境界

- 課題境界は提示順に生成される権限scopeであり、問題IDから答えへ分岐するキーではない
- 以前のHDS原理を候補として保持し、旧課題の観測格子を回答検索しない
- 固定位置型の転用対象は同値関係と補助定値。構造一般型は観測から導出した同型コレクションの同値/要素対応を独立した候補として再検証する。定値だけの格子モデルや、格子全体の答え表は転用しない
- 旧課題で既存HDSが3支持以上により採用していることが前提
- 新課題の予測後の異なる2観測について、既存HDS検証器を通す。同値関係はその条件値自体が2種類以上必要
- 固定位置型の入力形状は過去の支持範囲に限定。構造一般型は根容器型/葉型の範囲で新しい長さ・キーも扱う
- 反例があれば転用候補を隔離し、自動復帰させない。反証参照を保存する
- 現在課題の原理・複数の転用候補が矛盾すればHOLD
- 転用候補は最大64。候補の数を学習の成功率として数えない

局所的な関係の再利用を試す仕組みであり、2例で普遍的な法則を証明するものではない。

## 現段階の限界

固定座標の同値・値対応・定値に加え、同型構造の一様な要素関係を扱う。後者では新しい長さ・キーへ適用できるが、対象化、位置変更、構造合成、一般的な計画探索は未成立。36セルの明示予算は現在の二乗以上の推論・記録コストを抑えるためで、ARC全範囲を扱う能力はない。予算外はHOLDとして分母に残す。

小さな転用対照の3経験→2経験は、事前設定の支持閾値下での可否試験であり、一般的な学習速度向上の実証ではない。

新設試験を旧READMEの46試験の再現と呼ばない。公開trainingの局所得点を公式evaluation・private test・コンペ得点へ読み替えない。

## 構造関係の追加境界

詳しい型・支持・反証・懐疑権限は `設計/構造要素関係の最小拡張.md`。未知値と既知の矛盾が混ざった場合も既知の反例を保存し、完全な支持とはしない。親容器と子の予測競合はHDSで保留する。現行HDS保存形式は6とし、旧1〜5の読込は維持する。新しい関係を古いruntimeが無言で解釈しない。


## 観測Frameと明示的な再観測

`HDS学習機械(観測表現="配列階層")` はARCの元JSONの行・セル配列を保持する。既定の `座標辞書` と同じ値を損失なく表すが、HDSが観測できる容器境界は異なる。Frameは構築時に固定し、状態署名・保存物に含める。行選択や色変換の解法をAdapterへ追加するものではない。

適用文脈は型・固定長・固定キーを保持する。長さやキーの変動を支持経験で観測した箇所だけ反復型へ一般化する。未観測の軸変化、型変化、欠けた文脈はHOLD。旧hash-list文脈は従来の完全一致で解釈する。新HDS形式5は旧runtimeが拒否する。Adapter形式2はFrameと設定を含み、異なる実装のcheckpointを通常読込で自動移行しない。

```sh
python3 道具/観測表現を比較.py 比較   --教材 入力/公式ソース/ARC-AGI-2/data/training   --固定表 検証/学習環境/教材固定_追加100.json   --出力 出力/観測Frame_追加8比較
python3 道具/観測表現を比較.py 再観測   --旧状態 出力/追加8_凍結比較/継続最終checkpoint   --旧実装署名 e0100bcbb941e034a471a799597348dc2655b727467f7de7d369a1b7ba13eadd   --観測表現 配列階層 --出力 出力/配列Frame_55経験再観測
```

再観測は開発責任の明示的な状態再生成であり、自発的学習や新しい世界経験とは数えない。元実装・元論理状態・元ファイルhashを検証し、元経験と新経験の参照を一対一で記録する。旧経験55件は再処理後も55件、新規世界観測0件。旧checkpointは保存する。課題境界も保つ。新実装での自動採用結果は再検証され、旧原理を無条件コピーしない。

## 次の64セル比較の資源監督

`道具/資源制限つき継続評価.py` は各課題・各対照を別processで実行し、事前計画の壁時計上限と仮想メモリ上限を適用する。完了reportとcheckpointが揃った場合のみ状態を継続する。時間上限・メモリ上限・その他実行失敗は別分類で記録し、test全例をHOLDとして分母へ残す。未完了課題の部分更新を次課題へ渡さない。元checkpointは変更しない。

教材選択はtraining昇順201〜300番目のうち全格子64セル以下・train3〜8例の先頭8課題。100件中、形状予算超過76、経験数範囲外13、適合11件のうち件数予算除外3。選択と除外は得点測定前に固定する。Frameは配列階層、機械7aaf9b5cを保持し、55経験継続・新規連続・課題毎初期化を比較する。最大セル数36→64のみ明示的開発設定変更として署名前後を残す。

```sh
python3 道具/資源制限つき継続評価.py run --教材 入力/公式ソース/ARC-AGI-2/data/training --固定表 検証/学習環境/教材固定_追加64セル.json --計画 検証/学習環境/追加64セル_事前計画.json --旧状態 出力/配列Frame_55経験再観測/checkpoint --出力 出力/追加64セル_凍結比較
```

この事前計画は今回の開始checkpointの論理署名と二つの実ファイルhashへ固定している。生checkpointは大きいためGitへ含めない。別環境で前段の55経験再観測を再実行すると時刻により実ファイルhashが変わるため、同じ論理状態を確認したうえで、新しい実ファイルhashを持つ別の事前計画と、それを参照する固定表を作る。旧計画で通ったと偽らず、再現実験の新しい計画hashを記録する。

## 保存資源とcheckpoint公開境界

保存資源増分ではHDS形式5のbytesを保ち、一括文字列生成から逐次JSON書込みへ変更した。単一HDSファイルは同じdirectoryの一時fileへ書き、flush/fsync後に置換する。途中書込み・置換失敗では旧fileを保持する。電源断時の親directory永続性まで保証するものではない。

ARC Adapterの `保存する(directory)` は新規または空directoryだけを受理する。非空destinationへの従来の上書きは明示拒否し、既存checkpointを削除・変更しない。二つのfileを隣接一時directoryで完成させてからdirectoryをrenameするため、HDSだけ・境界だけの混在版を公開しない。更新保存には新しいdestinationを指定する。Generic HDSの単一file上書きAPIは維持する。

保存だけの実装変更でも通常のAdapter読込は実装署名違いを拒否する。`道具/保存互換を検証.py` は既知の旧7aaf実装について、旧論理状態を検証し、別一時directoryへ保存したHDSの完全なbyte一致と、境界の変更が実装署名だけであることを確認する。検証後だけ新規destinationへ公開し、失敗時に互換だと見えるcheckpointを残さない。元checkpointは保持する。これは開発者の互換検証であり新しい世界経験や内部学習ではない。


## 数量型の一般関係

`外部入力.文脈['数量経路群']` で明示した非負整数葉だけが数量一次関係の候補となる。Adapterは行数・列数を数量、色をカテゴリとして観測する。係数は3種類以上の入力数量からFractionで導出し、懐疑・独立検証・採用・反証を既存HDSで行う。外挿は観測幅一つ以内、結果が非負整数に閉じないとHOLD。複数の支持仮説が異なる結果を出す場合もHOLD。

詳しくは `設計/数量関係の最小拡張.md`。新しい型解釈・関係schemaは開発変更であり、内部学習は観測由来の係数・支持・反例・範囲の改訂である。HDS形式6を使い旧runtimeの無言解釈を防ぐ。以前の保存だけのbyte互換工具は、形式5→6でbytesが変わるため移行を拒否する。過去経験を数量型として再処理するなら、明示的な開発再観測を使い新規世界経験に数えない。

同一数量Frameでの機構除去は、次の四対照（数量有効/無効 × 継続/毎課題初期化）で実行する。各workerは既存の240秒/1536MiB監督を通す。

```sh
python3 道具/数量除去を比較.py --教材 入力/公式ソース/ARC-AGI-2/data/training --固定表 検証/学習環境/教材固定_追加64セル.json --最大セル数 64 --出力 出力/数量関係_最終64比較
```

数量無効時は、有効原理・係争原理の運用集合から数量を外し、採用抑止や転用の最終審査にも使わない。完全な記録集合は残し、無効中の反証は監査するため、再有効化した際に誤った数量原理が無条件に復帰しない。これは記憶消去ではなく機構の操作対照である。
