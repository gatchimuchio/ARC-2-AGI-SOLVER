# 同一学習機械の正動作・状態保持検証

## 結論

**以前できた出力を更新後も使えること、という要件は FAIL。**

同じ HDS インスタンスに既存の67規則経験を戻すと、3件目の後から、以前は出力できた5照会がすべて「断定保留」になる。予測値・元の経験・元の原理は保持されている。したがって今回の反例は、記憶消失として確認されたものではなく、別の対象系境界にある識別不能性が既存出力まで止める挙動である。

## 同一条件と観測結果

- 学習機械、エンジン、台帳、状態管理器、識別子生成器を同一プロセス内で固定。初期化・復元・取り替え・再教育はしていない
- 正常な基準能力を成立させる12経験の後、公開済み67経験の入力・順序・出典を変えずに1回ずつ投入
- 基準時点と毎回の追加後に10照会、計680照会。全10照会の予測値は事前登録した期待と一致
- 元々回答できた5照会は、67更新中の3～67件目で HOLD。利用可能な出力の不保持は325件 / 335比較
- 5照会は既存回帰と同じ格子恒等転用、既知値の同値、未知値の同値、有限対応の既知値2種
- 支持不足・未学習境界の空の「出力」は、回答成功には数えていない
- 元の12経験と新67経験は完全一致で保持。基準の6原理、状態履歴、全台帳の基準接頭部も維持
- 照会では学習状態と台帳を変えず、照会IDと学習判定IDの2カウンタだけが進む。完全なビット不変とは表現しない
- 機械的観測チェックは2031/2031通過。これは上の利用可能出力要件 FAIL を覆さない

## 最初に崩れた理由

3件目で追加された「既存規則経験再観測」境界の原理 ID 7～36 が、元の「監査_同値」等の照会へ6群の識別不能性として現れる。当該照会の境界ではこれらの支持・反証参照は空で、元の原理 ID 1～6 はそのまま正しい値を予測している。最初の失敗時点では隔離原理は0件なので、原因は隔離ではなく識別不能性の境界外伝播と切り分けられる。

該当コードは固定した v0.4.2 の次の経路。

1. 実行系.py 655～659行: 全有効原理を、照会対象の境界だけの経験とともに識別不能検出へ渡す
2. 適応.py 191～228行: 原理を照会境界で絞らず、同じ空の証拠集合を持つ別条件の原理群を識別不能とする
3. 排気系.py 17～23行: 識別不能群があれば全体を「断定保留」にする

予測そのものは適応.py 113～115行で境界を確認している。一方、後半では他境界の隔離も実行系.py 656、663～664行の全体保留に加わる。現行コードの実装に沿った挙動と、今回求められた出力保持要件への適合は分けて判定した。

`earliest-failure-evidence.json` と独立検査の `reviewer-earliest-retention-failure.json` は、最初の変化と原理参照を原出力から照合する。

## 同じ個体で続けた動作確認

上記保持結果を先に固定した後、別の明示的な合成テスト境界で19経験を追加した。元の67規則、基準経験・原理を変更する操作はしていない。

- 反例の記憶、初回隔離、隔離後の追加証拠、未審査反例を無視する復帰の拒否
- 合成テスト内だけでの明示審査後の限定復帰
- 条件の特殊化、親原理の再開放と系譜の記録
- 識別不能性と競合予測の抑止
- 不成立確認の区別、最大2条件という能力境界の記録と重複抑止

局所的な動作確認は55/55通過。67経験に由来する全体 HOLD は隠さず残したため、局所機能は境界・系譜・証拠参照・状態変化で確認した。これらは固定コードの契約に基づく新しい診断例であり、存在を確認できなかった過去の単体試験として扱わない。

## 変えていないもの・判定の限界

- HDS 12ファイル、接続、solver、runner、scorer、AGENTS、現在状態、公式入力を変更していない
- ARC公式採点は実行していない。従来の60/120課題・84/167例・全84格子一致という別の fresh-solver 回帰を、今回の同一状態保持と混同しない
- 現行 ARC 接続は課題を解くたびに新しい HDS を生成するため、過去の全60課題を解ける単一の保存学習状態は存在確認できない
- 67規則の意味的理解、共通原理の獲得、ARC改善、すべての未来更新への保証は主張しない
- 過去2回の67経験 native 保存は exit137。今回は同じ大規模保存を再試行せず、保存・復元成立を主張しない
- 同値・有限対応等の今回の限定範囲について、以前の出力が使えなくなる具体的反例を確認した。ゲートや中核の修正は行っていない

## 再現と証拠
