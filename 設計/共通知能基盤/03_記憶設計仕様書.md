# 記憶設計仕様書

## 0. 位置づけ

記憶はAGI三主体の一つであり、HDSが判断根拠として引用し、ミニドラが許可範囲内で計算に利用する可変保持主体である。

記憶は単なるログ、履歴、全文保存庫ではない。
将来のFrame、仮説、計算、採否、停止を実際に変える **現行知識構造** である。

## 1. 基本分離

記憶は最低限、次の二系統へ分ける。

```text
記憶
├ 事前記憶 Prior Memory
└ 実行時記憶 Runtime Memory
```

### 1.1 事前記憶

競技実行前に、利用可能な公式サンプル、正解、成功過程、既知事例、既存解析をHDSで構造化・完全解析し、定石と蒸留知識へ変換して格納する。

本構成では、事前記憶を主戦力として扱う。

### 1.2 実行時記憶

現在のARC世界で新たに得た観測、作用、結果、失敗、成功、因果、反例、局所定石候補を保持する。

実行時記憶は事前記憶を無条件に上書きしない。矛盾が生じた場合はHDSが修正・分割・無効化等を判断する。

## 2. ミニドラのPとの分離

HDS原典に従い、ミニドラ内部の命令形保持体Pと、AGIの可変判断根拠記憶を分ける。

```text
P_instr != M_mem
```

記憶は命令形候補や手続き候補を保持できるが、ミニドラの有効Pそのものとはみなさない。
Pへの昇格・変更は別の承認点を持つ。

## 3. 事前記憶の生成工程

事前記憶は、単純な答え表のコピーではなく、正解情報を根拠付きの構造知へ変換して作る。

```text
公式サンプル
正解 / 成功trajectory / 状態遷移
        ↓
HDS観測・Frame化
        ↓
局所因果・成立条件の抽出
        ↓
局所定石
        ↓
複数事例の水平比較
        ↓
水平引き算
        ↓
蒸留知識
        ↓
適用境界・反例・失敗条件付与
        ↓
HDS Gate
        ↓
Prior Memory
```

正解そのもの、完全trajectory、個別局面情報を保存してもよい。ただし、それらと再利用可能な定石・蒸留知識を同一レイヤーに混ぜない。

## 4. 記憶階層

推奨する論理階層は次とする。

### 4.1 原観測・出典記憶

- 公式サンプル由来情報
- 観測値
- 状態
- 作用
- 結果
- 正解
- 成功trajectory
- 出典
- 取得条件

### 4.2 既知解・再現記憶

- 既知の成功手順
- 既知の失敗手順
- 局所再現条件
- checkpoint
- rollback地点

### 4.3 定石記憶

- 状態条件
- 目的条件
- 推奨作用
- 期待結果
- 成立条件
- 失敗条件
- 代替手段
- 適用範囲

### 4.4 機構記憶

- entity / role
- relation
- action → effect
- precondition
- delayed effect
- transition rule
- causal chain
- invariant候補

### 4.5 蒸留知識

複数の定石・機構から局所条件を引き、再利用可能な上位構造として保存する。

例:

```text
個別成功A
個別成功B
個別成功C
   ↓ 水平引き算
共通機構
   ↓
上位定石 / 原理候補
```

### 4.6 反例・境界記憶

- 適用不能条件
- 反例
- 例外
- scope境界
- 破れた仮定
- negative transfer

### 4.7 Failure Signature

表面失敗ではなく、構造原因・発火条件・回復・次の観測軸・再利用チェックを保持する。

## 5. 記憶Record

概念上、各記憶は次の共通項を持つ。

```text
記憶Record := {
  記憶ID,
  種別,
  内容,
  抽象度,
  適用範囲,
  成立条件,
  反証条件,
  支持根拠,
  反対根拠,
  出典,
  観測条件,
  因果帰属状態,
  関連定石,
  関連機構,
  関連FailureSignature,
  信頼状態,
  更新状態,
  版,
  作成時刻,
  最終確認時刻,
  rollback先
}
```

すべてを物理schemaで同一化する必要はないが、意味責任は失ってはならない。

## 6. 状態

記憶は少なくとも次の状態を持てる。

- CANDIDATE: 候補
- ACTIVE: 現行有効
- PROBATION: 検証中
- DOMAIN_LOCAL: 局所限定
- CONTRADICTED: 反証あり
- INVALIDATED: 無効化
- ARCHIVED: 保管
- DELETED: 現行系から削除

「保存されている」ことと「現在判断に使える」ことを分離する。

## 7. 更新操作

記憶はappend-onlyにしない。

最低限、次を扱う。

- ADD / 追加
- REVISE / 修正
- MERGE / 統合
- SPLIT / 分割
- REPLACE / 置換
- INVALIDATE / 無効化
- DELETE / 削除
- ROLLBACK / 巻戻し
- ARCHIVE / 保管

更新にはHDSの承認を必要とする。

## 8. 検索権限

現在の問いに対して何を参照するかはHDSが決める。

```text
ARC世界
  ↓
HDS Frame
  ↓
記憶検索要求 {
  目的,
  現在構造,
  必要抽象度,
  scope,
  除外条件,
  最大件数,
  出典要求
}
  ↓
記憶候補
  ↓
HDS適用監査
  ↓
許可済み記憶集合
  ↓
ミニドラ
```

物理実装上ミニドラが検索関数を呼んでもよいが、検索目的・scope・許可条件をミニドラが独断で拡張してはならない。

## 9. 既知解と蒸留知識の併存

既知解を削除して抽象知識だけにする必要はない。

```text
既知解
= 再現・検証・最短適用に有用

定石
= 似た状態への再利用に有用

蒸留知識
= 未知状態への転用・合成に有用
```

三層を同時に持つ。

既知事例ではHDSが既知解を優先適用できる。
未知事例では、完全一致が無ければ定石・機構・蒸留知識を組み合わせ、不足部分だけを探索する。

## 10. 水平引き算

知識増加の目的はMemory容量を増やすことではない。

複数成功から共通構造を抜き、複数失敗から共通原因を抜く。

```text
経験増加
→ 局所知識増加
→ 比較
→ 差分除去
→ 上位定石へ圧縮
→ 重複局所知識を統合・降格
```

解析対象が増えるほど、上位知識体系は整理・圧縮される方向を目指す。

## 11. 作用後更新

世界の変化を観測しただけでは正本記憶を更新しない。

```text
作用
→ 世界変化
→ HDS再観測
→ 差分
→ 因果帰属
→ 既存記憶との矛盾監査
→ 更新候補
→ HDS承認
→ Memory更新
```

遅延作用、自然経過、外生変化、観測誤り、no-effectをaction effectへ誤帰属しない。

## 12. 事前記憶と実行時記憶の衝突

例:

```text
Prior:
  条件Aでは作用Xが成功

Runtime:
  条件Aらしき状態でXが失敗
```

即座にPriorを削除しない。
HDSは最低限、次を検討する。

- 条件Aの認識違い
- 隠れた前提
- 適用scope不足
- delayed effect
- observation error
- game / level固有差分
- Prior自体の誤り

必要に応じてSPLIT / REVISE / INVALIDATEを使う。

## 13. Provenance

事前記憶は必ず原情報へ戻れるようにする。

少なくとも次を保持する。

- source
- sample / task / game / level等の外部識別子
- 元観測
- 元正解または成功過程
- HDS解析版
- 蒸留元Record
- 更新履歴

外部識別子を保持することと、それだけで判断することは別である。

## 14. Memory Causality

記憶が存在するだけでは学習成立とみなさない。

有効記憶は、将来の次のいずれかを変えなければならない。

- HDS Frame
- 記憶検索結果
- ミニドラ入力
- 仮説集合
- 計画
- 採否
- 停止条件
- 探索量
- Failure回避

Ablationで当該記憶を外した場合に行動差が出ないなら、その記憶は少なくとも当該判断の因果要素ではない。

## 15. 禁止事項

1. ただログを増やすことを学習と呼ばない。
2. 参照されないMemory追加を能力向上と呼ばない。
3. 一回の成功を無条件に上位定石へ昇格しない。
4. 出典不明の蒸留知識を正本化しない。
5. ミニドラに独断の正本更新を許さない。
6. 事前記憶を固定真理として扱わない。
7. 失敗を追記するだけでFailure Signature化を省略しない。

## 16. 適合判定

記憶主体が成立したと言うためには、少なくとも次を満たす。

- Prior / Runtimeの区別がある。
- 既知解・定石・蒸留知識・反例・Failureを区別できる。
- HDSが検索scopeを制御できる。
- HDSが更新を承認・拒否できる。
- INVALIDATE / DELETE / ROLLBACKが実際に機能する。
- provenanceから元情報へ戻れる。
- 記憶変更が将来挙動へ因果的に反映される。
