# HDS設計仕様書

## 0. 位置づけ

本書は、HDS／人間意思決定理論そのものをAGI中心に再定義する文書ではない。
HDS Framework KernelをAGI Runtimeへ射影した **HDS Judgement Subject** の設計仕様である。

HDS本体の一次同一性は人間意思決定理論にある。ARC2 / ARC3はHDSのDomain Applicationであり、HDS本体の定義主体ではない。

## 1. AGI内での責任

AGI三主体におけるHDSは、次の責任を一貫して持つ。

- 世界を最初に受け取る入力主体
- 観測方法・対象・境界・Frameの確定
- 目的・価値・リスクの確定
- 未閉包項の検出とSUSPEND
- HDSコンパイラの実行
- 記憶検索条件と参照範囲の決定
- ミニドラへの計算要求生成
- ミニドラ出力の評価・反証・再計算要求
- 外部作用の最終採否
- STOP / SUSPEND / rollbackの決定
- 作用後世界の再観測
- 結果差分の因果帰属
- 記憶更新の採否

HDSコンパイラはHDS内部機能であり、第4主体として扱わない。

## 2. 世界入力境界

世界から得た値を、そのまま「世界そのもの」または「LLMが直接理解すべきData」とみなしてはならない。

```text
World
  ↓
HDS
  ├ 観測
  ├ 対象化
  ├ 差異化
  ├ 時間化
  ├ 空間化
  ├ 因果化
  └ 世界記述形成
  ↓
HDS Compiler
  ↓
ミニドラへ渡すData / Context / Question
```

神域境界として、認知後に形成した世界記述と認知以前の世界本体を同一視しない。

## 3. 上位境界

HDSは少なくとも次を保持する。

### U0 神域境界
認知後世界像を世界本体として断定しない。

### U1 認知形成監査
対象化・差異化・時間化・空間化・因果化・法則化・世界形成の過程を記録する。

### U2 TCP閉包

```text
W := (X, R, Mc)
```

X、関係R、閉包機能Mcによって、現在判断に必要な世界記述を閉じる。

### U3 誤投影監査
閉包済みW、有用な予測、安定した成功を、世界本体・本質・一般原理へ自動昇格しない。

## 4. 中核座標

各判断は次の二組の座標を持つ。

### 目的・価値・リスク

- 目的: 上位目的、現在目的、成功条件、失敗条件、時間軸
- 価値: 評価基準、方向、尺度、トレードオフ、適用範囲
- リスク: 不確実性、不可逆性、依存、損失、回復費用、停止条件

### 抽象・構造・認知

- 抽象: 何を同一視し、何を捨て、何を対象として切り出したか
- 構造: 関係、依存、因果仮説、遷移、制約、順序、Feedback
- 認知: 観測者、先入観、言語Frame、測定Frame、盲点、権限偏り

三位相は相互更新する。一つを変更したら残り二つを再監査する。

## 5. 標準循環 F / Md / Cm / U

### F: Frame / Ground
現在の対象、境界、目的、価値、リスク、観測可能範囲、資源、作用、停止条件、未閉包項を確定する。

### Md: Model
単一仮説ではなくModelSetを作る。最低限、必要に応じて次を含む。

- baseline
- alternative
- counter hypothesis
- null model
- no-op
- observation error
- delayed effect
- different goal
- adversarial
- counterfactual

### Cm: Commit / Check
Gate結果を統合して、採用・保留・棄却・次観測・次質問・作用・停止を決める。

### U: Update
作用結果を因果帰属した後に、局所モデル、証拠、主張、判断規則、チェックリスト、Domain Adapter、記憶を更新する。

更新は自動ではない。

```text
結果
→ 因果帰属
→ 局所修正
→ 再検証
→ 再利用候補
→ HDS承認
→ 正本更新
```

## 6. HDSコンパイラ

HDSコンパイラは、世界観測をミニドラが計算可能な入力へ変換するHDS内部処理である。

### 6.1 入力

- 世界観測
- 観測条件
- 現在目的
- 価値境界
- リスク境界
- 利用可能作用
- 資源予算
- 外部制約
- 現在記憶索引
- 過去の未閉包項

### 6.2 処理

1. 観測契約を固定する。
2. Open Termを検出する。
3. W=(X,R,Mc)を構築する。
4. 目的・価値・リスクを接続する。
5. 抽象・構造・認知を記録する。
6. 現在問いと必要計算を定める。
7. 記憶への検索要求を生成する。
8. 返却された記憶候補を適用範囲・反例・出典で監査する。
9. ミニドラへ渡す計算要求パケットを生成する。

### 6.3 出力契約

概念上の出力は次とする。

```text
HDS計算要求パケット := {
  現在目的,
  成功条件,
  世界記述,
  観測境界,
  抽象記録,
  構造記録,
  認知記録,
  未閉包項,
  証拠境界,
  記憶参照,
  利用可能作用,
  資源予算,
  可逆性,
  現在問い,
  計算要求,
  期待出力,
  反証条件,
  停止条件
}
```

内部schema名は日本語を正本とする。外部SDK等が要求する固定記号への変換はAdapterで行う。

## 7. Gate Stack

HDS Runtimeは必要に応じて次のGateを実行する。

- G00 座標Gate
- G01 Open-Term Gate
- G02 閉包Gate
- G03 不可能性Gate
- G04 反論対称性Gate
- G05 反論強度Gate
- G06 証拠Gate
- G07 妥当性・健全性・整合性Gate
- G08 再帰・矛盾Gate
- G09 誤投影Gate
- G10 可逆性Gate
- G11 時間・結果帰属Gate
- G12 資源Gate
- G13 影・局所機構・原理候補分離Gate
- G14 権限・制御所有Gate
- G15 Commit Gate

Gate結果は `PASS / SUSPEND / FAIL / NOT_APPLICABLE` を持つ。

## 8. HDS-BB / HDS-AI

未知環境ではHDS-BBを用い、内部本質を仮定せずI/O、摂動、反作用、ログから操作上必要な構造を推定する。

ミニドラ出力の監査にはHDS-AIを重ねてよい。

```text
ARC世界    → HDS-BB
ミニドラ出力 → HDS-AI
最終採否    → HDS Judgement Subject
```

モードを複数起動しても、最終採否権限は一つのHDS主体に集約する。

## 9. ミニドラへのFeedback

ミニドラの初回出力を外部作用へ直結させない。

```text
HDS
→ ミニドラ
→ 候補出力
→ HDS Gate
   ├ 不足 → 追加質問・反証・条件修正 → ミニドラ再計算
   ├ SUSPEND → 観測または情報取得
   ├ FAIL → 棄却・rollback
   └ PASS → COMMIT候補
```

HDSは必要なだけ内部循環を行い、G15 Commit Gateを通ったものだけを世界へ作用させる。

## 10. 作用後処理

作用後は必ず新世界をHDSが再受領する。

差分は少なくとも次へ分類する。

- action effect
- delayed effect
- time passage
- exogenous change
- observation error
- stale / redraw
- no effect
- multi causal
- unknown

因果帰属前に一般則や正本記憶へ昇格しない。

## 11. Failure Signature

失敗は表面ログで終わらせず、再利用可能なFailure Signatureへ変換する。

```text
FailureSignature := {
  失敗分類,
  症状,
  構造原因,
  発火条件,
  影響範囲,
  非影響範囲,
  破れた仮定,
  回復方法,
  次の観測軸,
  再利用チェック,
  再発回数,
  状態
}
```

Failure Signatureから次回のGate、Checklist、観測、記憶検索条件を更新する。

## 12. 不変条件

1. HDSは世界入力をミニドラへ素通ししない。
2. HDSコンパイラを独立主体化しない。
3. ミニドラに最終Commit権限を渡さない。
4. ミニドラに正本記憶更新権限を渡さない。
5. Open Termを暗黙補完で閉じない。
6. 一回の成功を一般原理へ自動昇格しない。
7. 結果帰属前に学習・記憶更新を確定しない。
8. ARC固有ID、score、API都合をHDS Kernelへ逆輸入しない。
9. HDSがSUSPEND / STOP / rollbackを実際に変更できなければ判断主体成立とはみなさない。

## 13. 適合判定

HDS接続が成立したと言うためには、少なくとも次を観測可能にする。

- HDSが入力Frameを変えるとミニドラ入力が変わる。
- HDSが参照記憶を変えると計算結果が変わる。
- HDSが反証条件を追加すると候補が再計算される。
- HDSが拒否した候補は世界へ作用しない。
- HDSが記憶更新を拒否した場合、正本記憶は変化しない。
- Failure Signatureが次回判断手順を変える。
- HDSを除去すると三主体循環が破れる。
