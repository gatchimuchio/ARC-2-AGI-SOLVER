# 専用学習機械の開発計画

## 目的と権威

Ownerの現在目的は「ARCリポジトリの専用ラーニングマシンを元に育て、ARCコンペで満点を出す汎用ラーニングマシンを開発する」ことである。目的は下げない。満点到達を保証せず、未測定を成立としない。

対象は `HDS/学習系統/v0.4.2`。学習機械が自分で経験を保持・推論・反証・改訂・再利用する。dotは教材提示、観測、原因調査、一般機構の開発を担当する。教師による正解解法の書込み、課題ID routing、答え検索、問題専用scriptは使わない。

## 二つの循環

- 学習循環: 実装固定 → 提示 → 予測確定 → 公開trainの結果・観測 → HDS内部更新 → 未教示例・後続課題
- 開発循環: 一般的な機構不足を実測 → 責任特定 → 最小変更 → 同一条件比較 → 回帰 → 差分監査 → 採否

開発変更を内部学習として数えない。コードの版、教材の版、経験順、支持・反例・適用範囲を残す。

## 段階

1. 教材環境と状態因果の検証
   - 正解の予測前遮断、最終評価非学習、継続記憶、再検証つき転用、保存復元
   - 新規機構対照と固定公開教材を分け、保持/消去/課題毎初期化を比較
   - この段階の合格は最終目的の完成ではない
2. 既存機械の表現と計算量の改善
   - HOLDを支持不足、未観測条件、競合、形状、資源超過へ分類する
   - 観測間の条件を識別する追加経験と、固定セルの偶然相関を拒否する範囲表現を検討する
   - 推論候補の全列挙・重複記録を測定し、既存意味を変えずに扱える格子規模を広げる
   - 一般的な関係合成等は、既存機能と責任を確認してから追加する。特定問題の成功を見て変換関数を注入しない
3. 広い公開trainingで継続学習と転用を測定
   - 固定した教材順・計算予算・学習版で未教示例を評価する
   - 問題横断の改善・回帰、初回必要経験数、再試行、転用成立条件、状態差を残す
4. ARC形式での凍結評価
   - 開発に使わない公開evaluationを封鎖し、凍結版で完全一致を測る
   - コンペ用形式・制約・再現性を確認する。公式実行規則は提出時点で別途確認する
5. 公式コンペでの到達検証
   - ローカル満点と公式満点を分ける。非公開testを取得しない
   - 実際の提出、外部課金、追加認証が必要ならその行為についてOwner確認を得る

どの段階でも満点未達の限り目的は未達として維持する。取得できる証拠やCPU実験を継続し、未解決の判断・必要資源が具体化した場合に報告する。
