# リポジトリ運用モデル

## 目的

戦略より先に、判断主体・現在状態・証拠・外部境界を混同しない開発環境を固定する。

## 四面

```text
規範面    = AGENTS / 権限順序 / 選択中の仕様
選択面    = 制御/現在状態.json
証拠面    = code / tests / runtime / official result
履歴面    = Git履歴・削除済み旧資産
```

Current Stateは選択面だけから読む。履歴面は自動的に現在権威へ戻さない。

## 作業順序

```text
Owner目的
↓
現在状態
↓
対象世界・入力資産
↓
HDSによるFrame確定
↓
HDSコンパイラ
↓
ミニドラ計算
↓
HDS判断
↓
実装または出力
↓
検証
↓
観測結果
```

## ARC2公式入力

`入力/公式サンプル/`と`入力/公式ソース/`は原入力。将来これをHDSで完全解析してPrior Memoryへ蒸留しても、原入力そのものとは分離して保持する。

## 状態遷移

戦略・現在作業・完成状態の変更は、Owner指示または選択済み戦略の明示的な遷移条件がある場合だけ行う。test PASSやartifact生成を理由に暗黙遷移しない。
