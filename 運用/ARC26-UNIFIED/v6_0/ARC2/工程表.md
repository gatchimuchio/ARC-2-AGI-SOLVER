# ARC-AGI-2 専用工程表 v6.0 — 既存資産→実格子→公式得点→改善

各工程は**着手する実行コマンドと結果**で区切る。出力やテスト作成だけで次工程の達成としない。

## 実行1：現行基準線と既存公式採点の回収（最初に行う）

作業ディレクトリ：\`ARC-2-AGI-SOLVER\`ルート。環境が存在する場合は既存のlockで固定。

\`\`\`bash
git status --short
git rev-parse HEAD
python -m uv run --locked python -m 接続.Kaggle操作 接続確認
python -m uv run --locked python -m 接続.Kaggle操作 履歴
python -m uv run --locked python 検証/ARC2評価.py --mode current
\`\`\`

既存Kaggle提出\`57560705\`の**現在のステータスと数値**を確認。既存提出があれば同一版を重複送信しない。コマンドの引数・形式が現行版と異なれば\`--help\`とソースで確認し、その理由と修正コマンドをログに残す。

採点では公開120題（167出力格子の過去記録）と現行実処理母数を突合。**スキップ、時間超過、HOLDを母数から消さない**。ログに解答候補・誤答分類・処理時間を残す。古い120/120記録を現行のスコアとして転記しない。

成果：実行ID、HEAD、HDS/memory版、公開正答格子数/総数、HOLD、所要時間、公式履歴。

## 実行2：得点ゼロに直結する欠陥の修正

1. \`接続/ARC2/HDS接続.py\`に至る学習機械への実際の呼出経路を追い、候補HOLD・衝突の過剰伝播を是正。trainを満たす生成仮説を独立して評価。
2. \`記憶/事前記憶/v0.4\`の一般的変換機構を適合させ、公開training例と組み合わせて新しいtest格子を推論。課題ID別答えに変換しない。
3. \`接続/ARC2/Kaggle提出.py\`の「入力コピー・同一2候補を成功と見なす」構造を是正。2候補の独立寄与/HOLDを可視化。
4. 不適切な成功条件を持つ\`検証/test_ARC2Kaggle提出.py\`等を**新しい望ましい動作を検証するテスト**へ更新。
5. **変更前と同じ公式公開評価コマンド**を実行。正答・HOLD・未処理・時間の差分を出し、成績が悪化すれば原因を突き止め採否を判断。

成果：入力→HDS→出力格子の実トレース、初回比pass@1/pass@2・実正答数。

## 実行3：学習成立の実験

同一の未見課題群に対し、学習・適応を行う前の状態Aと、公開train例/許される観測で汎用規則を更新した後の状態Bを比較する。保存するのは**機構・規則の状態差分、train exact、未見pass@1/pass@2差分**。評価正解は最後の採点器だけが使用。未見評価で改善がなければ「学習効果未実証」と記録し、失敗機構を修正。

成果：「学習機械が読み込まれた」ではなく、実際の学習動作と未見得点差。

## 実行4：Kaggle本番版の構築と実行

以下は過去に確認したリポの実行経路。現行の\`--help\`/\`README\`と照合する。<ID>は**新しい出力ディレクトリ名**に置換する。

\`\`\`bash
python -m uv run --locked python 道具/ARC2Kaggle提出bundle.py --output 出力/Kaggle/<BUILD_ID>
python -m uv run --locked python 道具/ARC2Kaggle提出bundle.py --stage-upload 出力/Kaggle/<BUILD_ID> --output 出力/Kaggle/<UPLOAD_ID>
python -m uv run --locked python -m 接続.Kaggle操作 送信 --folder 出力/Kaggle/<UPLOAD_ID> --timeout 43200
\`\`\`

条件：

- \`bundle.py\`の\`_runtime_files()\`がHDSと**公開・一般化可能な事前記憶**を本当に同梱したか、梱包ファイル一覧と内容hashで確認。事前記憶内の公開正解/ID別答えの不正実行使用は除外。
- Kaggle Notebookで\`arc-agi_test_challenges.json\`の**全task IDと全test入力**に対し順序を守り正しい\`submission.json\`を作る。前回は240 task/259格子という観測だったが実際の入力から動的に数える。
- 隔離環境の時間・RAM・無ネット条件、HDS稼働・記憶ロード・各出力の推論実行率をログで検証。
- 新Notebook実行IDを取得し\`接続.Kaggle操作 状態 --record <RECORD>\`、\`出力 --record <RECORD> --path <NEW_OUTPUT_DIR>\`等で検証。
- 既存提出枠と公式ルールに沿い、推論能力が改善した版を\`接続.Kaggle操作 提出 --record <RECORD> --message <MESSAGE>\`で競技提出。現行CLIの仕様に必ず従う。
- **Notebook COMPLETEだけで終了禁止**。\`履歴\`で当該提出IDの**公式確定点**を確認し、版を台帳へ固定。

成果：公式ID・Notebook版・確定数値＋ローカル実力との対応。
