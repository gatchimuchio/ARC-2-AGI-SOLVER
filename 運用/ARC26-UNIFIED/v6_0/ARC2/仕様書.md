# ARC-AGI-2 専用仕様書 v6.0

対象リポ：[gatchimuchio/ARC-2-AGI-SOLVER](https://github.com/gatchimuchio/ARC-2-AGI-SOLVER)。共通仕様書と本書を合わせて使用する。**ARC3の操作仕様をARC2に流用しない。**

## 1. 競技上の目的

**既存のHDSラーニングマシンと解析資産から、初見のARC2格子を実際に正解する**。公開問題で再現性と学習の効果を測定し、Kaggle本番の\`submission.json\`を公式採点に通してスコアを上げ、首位を目指す。

Kaggle公式スコア：各taskの各test入力に対し、\`attempt_1\`または\`attempt_2\`が正解格子に**完全一致**ならそのtest出力に1点。全test出力の平均。**JSON全件生成≠得点**。85%は公式追加賞の目標ライン、最終目標は首位/最大得点。

公式：[Kaggle ARC2](https://www.kaggle.com/competitions/arc-prize-2026-arc-agi-2)（2026-10-27確認）。

## 3. 現時点の主要欠陥（初回修正候補）

1. 以前のNotebook出力は**259 test出力中258件がHOLD由来のfallback**。この形式完成を成果と扱ったことが最初の設計不良。
2. \`Kaggle提出.py\`のHOLD時入力コピーを「予測」として扱い、\`attempt_1==attempt_2\`を無条件作成。正答の計測からHOLD由来は独立計上する。
3. \`HDS接続.py\`の候補集合では一部HOLDや衝突が**全候補拒否**へ伝播する恐れがある。成立した変換仮説・候補の個別検証、採否と順位を作る。
4. \`道具/ARC2Kaggle提出bundle.py\`が\`記憶/事前記憶/v0.4\`を搭載していなかった。ローカルだけでなくKaggleの隔離環境でも学習記憶が使われるようにする。
5. \`検証/test_ARC2Kaggle提出.py\`がHOLD入力コピーと2候補複製を正としていた。目的に合うテストへ変更する。
6. 過去アーカイブで公開評価120/120課題・167/167格子正解の記録があるが、現在のCPU・時間制限付き経路では再現性未確認。**過去版に何があって現行で何が失われたか**を資産比較し、解答直接流用なしで推論機構を回復する。

## 4. 必須動作・禁止事項

**必要動作**

1. 任意の公開train入出力組から構造変換・対象物・空間関係・色役割等の一般化候補を抽出、妥当性をtrain全例で実証。
2. 候補をtest入力へ適用し、候補の成立条件と出力格子を生成。**train正解を再現する**ことと**test正解を得る**ことを分けて測る。
3. 候補に複数案があるときは**異なる妥当な2案**を出す。1案しか無ければ形式上2欄が必須でも、複製を「2回試行による解決能力」とは報告しない。
4. 認識不能の入力コピーは、**同一変換が実際に推論できた場合を除き**推論成功と呼ばない。HOLD率、fallback率、候補衝突率を実正答率とは別記録。
5. 解析資産から汎用機構を実装知に変換し、学習前後の仮説・適応・未見の成功率差を保存する。
6. Kaggle offline Notebookが\`train\`以外の正答や評価正解へアクセスせず、記憶・エンジンを本当に実行できることを検証。

**禁止**：task ID/ファイル名/入力hashと固定正解格子の照合、評価正解を実行器に渡すこと、許されない私的情報の使用、評価スコア向上を名目とした答え表の蒸留、出力全件や形式検査の成功をスコアと呼ぶこと。

## 5. 正しい採点と検収

- 公式の評価器が参照する\`evaluation_solutions\`は**採点時のみ**。推論プロセスにはtest入力だけ。
- 公開スコア：**格子完全一致のtest出力数/総test出力数、pass@1とpass@2、試行2の独自寄与、HOLD数、誤答数、時間超過・未処理数**。多test taskの格子順序も公式に一致させる。
- 既存評価器の制限（前回CPU10s/task・RAM512MiB・全体wall60s等）は現行環境で確認し記録。処理対象が120題/167格子の全件に達しなければ未処理を母数から消さない。
- 同版2回の計測、変更前後同条件比較、残る失敗の機構別内訳（抽出・候補生成・候補採否・記憶参照・処理時間）。
- 公式スコア：**競技提出ID・Notebook版・確定数値**を一組として記録。初回の低得点でも結果を隠さず、次の具体的失点改修へ進む。

**目的未達の状態**：全件HOLD、ほぼ全件入力コピー、2候補複製だけ、完走したがスコア未観測、旧アーカイブ高得点を現在値として引用。これらではCodex作業完了としてはならない。
