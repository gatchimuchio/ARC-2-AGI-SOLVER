## 絶対目標

**ARC2の格子を実際に解き、再現できるローカル実績と学習機械の成立を示し、Kaggle公式スコアを出して向上させ、勝利を狙え。** 初回提出、形式のPASS、HOLD検証は目的でない。

## 今すぐ行う（順序を入れ替えない）

1. 現行HEAD、\`AGENTS.md\`、\`制御/現在状態.json\`、旧文書と提出台帳、HDS・事前記憶・公式サンプル・実行接続を棚卸し。**今回のv6は新Owner指示**。旧v1/v5等の失敗記録は保存。
2. 工程表「実行1」のコマンドを本当に走らせ、**現行版で格子が何個正解したのか**を確認。公式提出\`57560705\`の状態と得点も確認。
3. 失点の現象を**入力コピー・同一候補・HOLD・未処理・候補否決・記憶非接続・時間超過**に分類し、スコアの落ちている主要原因を特定。
4. 工程表「実行2」の**実出力生成器**を修復。過去120題/167格子の成功記録を調べるが、当時の正解をtask IDで参照して得点を作らない。
5. 工程表「実行3」の適応前後・未見出力の実験を実施。状態の変化だけでなく**正答率の差**を示す。効果なしは失敗として次の修正へ。
6. HDS・記憶を同梱するNotebookを作り、公式ルールに沿って**公式スコアが確定するまで追跡**。その後も失点修正→再測定。

## 禁止する停止・成果報告

- 「submission.jsonが生成されたのでPASS」「259欄を満たしたので達成」「テストを通したので完了」。
- 「PENDINGなので開発も止めます」。公式状態は追いながら公開データの推論能力改善を続ける。
- 「歴史的120/120があるので現在も満点」。版・評価条件・漏洩なしの推論を再現してから評価する。
- 「記憶がindex内にあるので使った」。**Kaggle実環境の呼出/ロードをログで示す**。
- 「HOLD時に入力を返せば2候補完成」。推論なしを成功と偽らず、2候補の付加価値を分けて測る。

## この指示書の検収条件（実測必須）

| 検収 | 証拠 |
|---|---|
| 現行版の得点を把握 | 公開採点の実結果、母数、失敗分類、run_id |
| ラーニングマシン稼働 | 任意のtrainからtest出力を作るHDS/記憶の呼出ログ |
| 再現・比較 | 同コード/同入力/同制限の2回実行、修正前後のpass@2等 |
| 学習実証 | 適応前後の内部規則・記憶差分、未見対象の得点差 |
| 本番稼働 | 公式Notebook出力と実際の採用ロジック・記憶の整合 |
| 公式得点 | **当該版と一致する確定Kaggleスコア**、提出IDと時刻 |

数値が低くても隠さず報告し、次の失点改善に使う。**公式スコアの改善まで開発は継続する**。十分な正当理由がある実行不能時のみ、実エラーと必要な最低限のOwner操作を提示。
