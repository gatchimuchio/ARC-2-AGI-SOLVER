# 共通仕様書 v6.0

対象：ARC Prize 2026のARC-AGI-2とARC-AGI-3。最新Owner指示を意味上の正本とし、各リポのAGENTS・旧正本・コード・公式ルールを照合して実施。

## 1. 目的・成立条件

**最終目的：既存のHDSラーニングマシン（\`HDS/学習系統/v0.4.2\`）で実際に課題を解き、Kaggle公式のスコアを継続的に獲得・改善し、ラーニングマシンの成立を実証し、優勝を狙う。**

必要な機能循環は「公開事例・既存解析・記憶→推論→実行→正誤/状態変化の観測→記憶・方針の更新→未見対象へ再適用」。ARC2は格子出力、ARC3はゲーム行動という形式が異なるだけ。

| 実証対象 | 必須観測 | 証拠にならないもの |
|---|---|---|
| 実際の課題解決 | ARC2の格子完全一致、ARC3の攻略・行動効率 | JSON生成だけ、Notebook COMPLETE、RESET後停止 |
| 学習・適応 | 観測を契機とした内部状態と推論/行動変化、未見例への結果 | 記憶が存在する、学習例を読んだ、既知例を暗記 |
| 再現性 | 入力・版・条件・結果を固定した再実行と変更前後比較 | 過去の別版の数字、手作業でしか再現できない成功 |
| 公式スコア | Kaggleの確定数値と提出ID・Notebook版・実行資産の対応 | ローカル得点、KaggleのRUN COMPLETE、PENDING |

局所試験は手段。**高スコアと勝利が確認されるまで競技目的は継続**する。学習実証と競技スコア実証は併行するが、一方だけで他方の成立を主張しない。

## 2. 既存資産の使用を義務とする

1. \`AGENTS.md\`、\`制御/現在状態.json\`、\`運用/\`、git履歴を確認し、当時の成功値の環境を把握。
2. \`HDS/学習系統/v0.4.2\`の能力と限界、\`記憶/事前記憶/v0.4\`の**一般化可能な内容**、\`入力/\`の公式課題、\`接続/\`・\`道具/\`・\`検証/\`を棚卸し。
3. **学習機械と記憶が本当に実行経路に載っているか**を、入力から格子/操作が出るまで呼び出し追跡。存在確認で終えない。
4. 新しい空の実装に置換せず、失点に直結する欠落だけ修正する。既存の良い資産を喪失しない。
5. テストがHOLD、入力コピー、RESET即停止を「正解」と認めていたら、**テストの期待値自体が目的に反する**。機能とテストを同時是正する。

## 3. 再現性（毎回の評価で必ず記録）

\`\`\`text
run_id, date_utc, track, git_commit, learner_code_version,
memory_manifest_hash, input_dataset_version/hash, scorer_or_sdk_version,
execution_command, runtime_limits, seed_if_any,
output_or_trace_hash, local_metric, official_kernel_version,
official_submission_id, official_metric, status, limitations
\`\`\`

- 元データ・主要出力・操作履歴・失敗分類の保存場所も追記する。既存の運用台帳へ**追記**し、古い結果を上書きしない。
- 変更前Aと変更後Bは、ARC2なら同一問題群/採点器/制限、ARC3なら同一公開ゲーム群/操作上限/終了条件で比較。
- 同じ版を2回実行し、期待される決定論と実結果を照合。差異があれば原因を分類し説明する。
- 過去アーカイブの満点は現行版の公式得点と混同しない。再現不能なら条件不明と記し、現行条件の基準線を作って開発継続。
- 学習評価は、対象の未来の正解を渡さず**適応前後の内部状態と未見結果**を比較。改善しなければ「学習効果未実証」と記す。

## 4. 競技に適合させる

- ARC2：各テスト出力に\`attempt_1\`,\`attempt_2\`の二候補。**どちらかが正解格子と完全一致**でそのテスト出力が1点、総test出力平均。目標は85%以上の賞ラインを超え、首位を狙う。テスト正解・ID・ファイル名を使った固定解答表禁止。
- ARC3：実際の環境を観測し合法行動でレベルを突破。公式は人間基準に対する行動効率も採点し、全ゲームの人間水準攻略で100%が目標。ゲームIDごとの固定操作列、隠れた状態への依存禁止。
- **HDSの候補HOLDと、外側の合法な情報収集行動は異なる**。内部候補を無審査承認してはいけないが、正当な実行判断が許す観測・試行まで停止させない。

## 5. 実際に発見済みの失敗を修正する

| 対象 | 前回観測の阻害要因 | 取るべき方向 |
|---|---|---|
| ARC2 | 提出履歴259テスト出力のうち258はHOLD由来fallback | 格子推論、候補採否、記憶の投入を実稼働させる |
| ARC2 | 未根拠の入力コピーと同一2候補、旧テストで正とされる | 生成候補の妥当性と非コピー依存の出力を測る、誤テスト変更 |
| ARC2 | 過去120題/167格子のアーカイブ正解が現行版で不明 | 元版の条件を照合し現行採点で再現、ただし正解漏洩しない |
| ARC3 | \`MAX_ACTIONS=1\`・RESET/HOLDで停止 | 実ゲームで観測→合法行動→結果→更新を繰り返す |
| ARC3 | 全HDS候補\`実行許可:false\` | HDSと独立し許可された探索行動を判断・実行する層 |
| 両方 | 提出bundleに\`記憶/事前記憶/v0.4\`が載らない | 公開利用可能な一般化記憶だけ梱包し現地読込を検証 |
| 両方 | 既存公式提出のPENDING | 提出IDを追跡しながらローカル改善を続ける |

## 6. 権限・保持

Kaggle規約・実行上限・提出枠・公開条件を守る。評価正解や非公開内容を実行器へ混ぜない。Git履歴・旧仕様・成功資産を保存し、保護された\`AGENTS.md\`と\`制御/現在状態.json\`を無断変更しない。他リポや無関係な基盤を改変しない。未確認のスコア・勝利・学習実証を捏造しない。
