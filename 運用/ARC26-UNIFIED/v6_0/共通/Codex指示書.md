# 共通Codex実行指示書 v6.0

## 今回のOwner指示

あなたが実現すべきものは**実際のARC問題解決・ゲーム攻略によるKaggle公式スコア獲得と改善**、および**学習機械の成立を再現性のある実験で示すこと**。競技優勝を目標とする。

この共通3ファイルと、作業リポに対応する専用3ファイルをすべて適用する。違うトラックの作業を混ぜない。旧文書に「まず提出成功/HOLDの証拠」「PENDING待ち」があっても、Ownerの本指示に合わせ実働工程を優先する。旧文書と観測履歴を消さない。

### 初回操作

1. \`git status\`、\`git rev-parse HEAD\`、\`AGENTS.md\`、\`制御/現在状態.json\`、既存正本・テスト・成功証拠・提出台帳を確認。手元に既存変更があれば保全。
2. \`HDS/学習系統/v0.4.2\`、\`記憶/事前記憶/v0.4\`、\`入力/\`、\`接続/\`、\`道具/\`、\`検証/\`を**入力→推論→解答/行動→評価**の呼出経路で突合する。
3. 直近Kaggle提出を**提出IDとNotebook版で照会**し、PENDINGや別版スコアを現行値にしない。
4. 専用工程表の「実行1」へ直行し、現行版の正答/攻略性能を計測する。

### 実装順序

1. ARC2/3の個別指示書が特定する**現在の致命的な失点源**をまず直す。
2. 現行学習機械と事前記憶を本番実行経路で実際に使用する。一般化機構と記憶形式は保持。
3. 記憶・推論・適応の状態遷移を観測可能にする。未見集合で学習前後を測る。
4. 同条件の得点比較で良くなったものを採用。Kaggle採点して公式数値を取得し反復。
5. 上記を支える範囲だけ梱包・テスト・文書を修正する。

**間違った旧テストのPASSを守るために誤実装を残してはならない。** テストが「入力コピー」「2候補複製」「1手停止」を正と認めるなら、望ましい行動を検査するよう仕様とテストを改める。

### 実験・台帳

- 全実行を一意の\`run_id\`に紐付け、コード版・HDS版・メモリhash・入力/SDK版・seed・制限・コマンド・実測結果・結果ファイルhashを追記。
- 変更前後で同じ公開評価条件を使い、かつ同版再実行で再現を検証。差異・失点・失敗は消さない。
- 過去アーカイブの値は「過去観測」。今回再現できるまで現行能力とみなさない。
- 学習効果なしならなしと報告し、該当機構を修正する。形式的な\`memory_loaded=true\`を実証としない。

### 詰まった時の行動

- 正答0/HOLD多発/RESET即停止：**目的未達の障害**として原因とコード・誤テストを是正し継続。
- Kaggle PENDING：同じ提出IDの状態を後で再照会、同時に公開データで失点改善。重複送信による日次枠浪費を避ける。
- HDS内部不採用：HDSを勝手に採用へ変えず、外側の独立した適切な行動判断で合法な試行を可能にする。
- 認証不備/競技ルール/実際の権限不足：**試した正確な操作とエラー、必要な最小の承認だけ**Ownerに報告。禁止操作の迂回はしない。

### 版管理

最初の実採点を行った後、同じ実行単位の中でこの6文書を対象リポの\`運用/\`へv6として配置し、旧版と対応を記録。**文書登録を待ち状態にせず実力改善を先行**。保護対象\`AGENTS.md\`、\`制御/現在状態.json\`は勝手に変更しない。元資料・Git履歴・比較前版を保存する。文書配置やテストだけで作業完了扱いしない。
