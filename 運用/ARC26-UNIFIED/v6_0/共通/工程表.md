# 共通工程表 v6.0 — 得点で前進させる

**最優先：既存ラーニングマシンで実際の課題解決を再開し、実点を測る。** 資料整理や提出経路の整備は従属作業。

| 工程 | 共通作業 | 計測結果/次の工程への条件 | 失敗時 |
|---|---|---|---|
| P0 現状確認 | HEAD・AGENTS・機械・記憶・公式サンプル・評価・Kaggle履歴を確認 | 実得点へ至る経路と阻害箇所が判明 | 接続欠落を特定。資料整理で停滞しない |
| P1 現状得点 | **現行版の公開課題を直ちに実行・採点** | 現行HEAD/条件と結び付く正答・進行・効率 | 0点でも記録してP2へ |
| P2 実働修復 | 学習機械、事前記憶、公式サンプルを提出実行経路へ接続 | ARC2が格子を推論／ARC3が多手数で攻略 | 局所エラー原因を直し再試行 |
| P3 学習実証 | 記憶→推論→結果観測→適応を実行、未見対象で前後比較 | 状態変化と学習効果の有無が測定済 | 効果なしも記録し改善 |
| P4 高得点化 | 失点の多い機構から、最小変更→同条件全体採点 | 前版比較と失点分類の変化 | 失点修正を戻す/再設計し成功版維持 |
| P5 公式実証 | 競技ルールに沿い提出→公式確定スコアを回収 | Notebook版・提出ID・数値・コード/記憶版を紐付け | PENDINGなら追跡しつつP4継続 |
| P6 競技循環 | P4↔P5を締切まで反復、公式最善版選定 | 最良の**確認済み**スコアと再現可能な版 | 権限など阻害事実のみ報告 |

工程表は**固定期間の書類承認待ちではない**。P0/P1は短く行い即P2へ。PENDING、局所0点、未確定資料を理由に実能力改善を止めない。

## 直近実施

1. **現在の公式提出結果**を既存IDで検索。ARC2では258/259 HOLD、ARC3ではRESET/HOLDが現行でも起きるか局所再実行して観測（過去観測を現在と断定しない）。
2. ARC2は実格子生成、ARC3はゲームを複数手進める振る舞いを復旧。失敗した検証の期待値自体も修正。
3. 同一評価集合・制約で前後比較。メモリが使われた証拠と学習前後差を採録。
4. 提出枠と公式得点状況を見て実力改善版を公式に提出し、公式数値を確認。
5. 最大失点機構を修正して繰り返す。最新結果の記録は**追記型**。

## 統一台帳の最低項目

\`run_id | track | git SHA | HDS/memory hash | input/SDK | local_before | local_after | official_submission_id | official_score_or_pending | reproduction | next_failure\`

同じ版で二度走らせた差分を記録する。改善時は前後の比較環境を固定し、異なる対象・採点法の値は別系列にする。

## 期限と判断

公式掲示の最終提出期限は2026-11-02 23:59 UTC／11-03 08:59 JST。最新の公式ルールで再検証。締切時点には確認済み最善版を指定する。**初回提出・0より大きい初回スコア・局所テストPASSは中間結果であって完了ではない**。

セッションの切れ目では台帳に「いま使える最善版」「失点の最大原因」「次回の最初の実行コマンド」を追記。Codexは次セッションに同じ観測作業をやり直さず、その続きから実行。
