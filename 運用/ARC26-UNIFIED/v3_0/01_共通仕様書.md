## 1. 最上位目的

**ARC Prize 2026のARC-AGI-2とARC-AGI-3で勝つこと。** 既存のHDS学習機械、公式サンプル、解析・記憶・攻略資産を公式採点に接続し、**公式の数値スコアを実測してから**その数値に従って学習・推論・行動・提出を改善する。最終提出日まで両大会で原則毎日1回ずつ提出し、最良の版を最終選択する。

Ownerの工程指定は「現状の資産を使ってまず実際に提出してスコアを出す→そこから開発する」。スコアなしの最適化計画は受入不可。**初回公式スコア0は有効。未採点と0点は違う。** 初回スコア後の改善・日次提出は委任済みで、工程の区切りごとに追加承認待ちを作らない。

旧3点セットの設計欠陥は、提出ファイル、Notebook COMPLETE、Kaggle受付PENDING、ローカル成績、公式数値を混同し、**実動作を備えていない基線**を「開発が進んだ」と見なし得たこと。本書の品質ゲートで再発を防止する。

## 2. 共通管理・固有実装

| 共通化するもの | 分離するもの |
| --- | --- |
| 目的・工程・品質ゲート・公式スコア取得・証拠形式・日次運転・Codex作業指示 | 別々のmain、HDS接続、ARC2格子ソルバー、ARC3ゲームエージェント、入力・記憶、Kaggle提出ID、得点尺度、認証 |

- 共通3文書は2リポを統合する指示ではない。各repoの現在の実装、AGENTS、学習データの境界を守る。
- HDSの現行正本は各repoの`HDS/学習系統/v0.4.2`。関連理論資料の別版へ無断で移行しない。
- Windows-first。WindowsのCodex・Python・Kaggle CLIを主系、MCPは検証可能な補助。WSL・言語変更・全面再実装を計画の前提にしない。
- 課題ID・ファイル名・hashによる答え分岐、固定解答表、ゲームID別の固定行動、hidden正解の利用、評価情報の推論側流入は禁止。
- 「学習した」は記憶→推論→適応の内部動作を追跡して判断する。「勝てる」は**公式実測点・再現性**で判断し、試験数・解析ファイル数を性能の代わりにしない。

## 3. 指示・権限・証拠の保持

Ownerの最新原文指示→各repo`AGENTS.md`→保護対象`制御/現在状態.json`→現コード・テスト・公式結果→本3文書→過去文書の順に照合。保護ファイルはOwnerの明示許可なしに改変しない。`自動遷移:false`を独断で書き換えない。進捗と再開位置は別の新規台帳に置き、既存の状態を理由に許可済みの観測・提出追跡・能力接続を無意味に停止させない。権限衝突が実在する場合は対象行を特定して報告。

Git mainを正本。強制push・履歴書換え・既存証拠の削除・無関係refactor禁止。旧版の失敗や公式記録は追記保全。各作業開始・再開時にAGENTS、main SHA、git status、Kaggleルール・提出枠を再読する。秘密鍵・非公開学習データを公開リポへ入れない。

## 5. 公式スコア成立条件 G-SCORE

次を**同一の提出ID**で満たした場合だけ「公式スコア取得」と呼ぶ。

1. 公式大会slug、submission ID、Notebook slug/version、source SHA、提出日時、入力・出力SHA256を保存。
2. Kaggle公式の現在のstatusを取得し、**採点完了後の数値score**を原値・尺度・観測時刻・取得経路とともに保存。`0`はPASS、空欄・null・PENDINGはHOLD。
3. 失敗なら公式エラーとNotebook/Competition Rerunログを保存し、入力・形式・Notebook実行・送信・採点のどこで止まったかを特定し、最小修理する。
4. その提出物の実際の作用を付随保存。ARC2ならHDS出力/HOLD/代替/時間切れ、ARC3なら合法行動/レベル進捗/ゲーム進捗/HOLD/エラーの件数。
5. Notebookの`Save & Run All`や`COMPLETE`と、**競技への提出と公式採点完了**を別の証拠として追跡する。

数値未取得中にできるのは採点照会・環境修理・現資産の実動作検査・後続の準備。数値なしに「公式スコア改善」と主張しない。PENDINGでは同じ提出を再送せず、一定間隔で同一IDを追跡。失敗時は次の適法な提出枠で採点まで完走する。

## 6. ARC-AGI-2固有要求

- 経路：`接続/ARC2/HDS接続.py`→`接続/ARC2/Kaggle提出.py`。各タスクの公開train入出力とtest入力だけで候補を作る。正解はローカル評価の親過程だけに保持。
- `検証/ARC2評価.py`の120課題評価、本番形式の240課題259格子、Kaggle hidden評価を混同しない。実行時にchallenge課題数・test数・順番を読み取る。120/167・120/172・240/259を本番ループに固定しない。
- **HOLDを隠さない。** `attempt_1/attempt_2`が合法なだけでは解答にならない。HDS確定解/代替出力/失敗/タイムアウトを全格子分離して記録し、258/259 HOLDの機構別原因を観測する。
- 初回公式score取得後、汎用規則の支持条件・候補形成・反例隔離・第2候補を改善。過少/過剰支持や異なる事前教材の干渉を実測し、既存正解の回帰を防ぎながら未見課題への汎化を狙う。
- 二つ目の妥当な候補が成立すれば`attempt_2`に採用。単一候補の複製は形式の保険であり、性能改善と報告しない。失敗・HOLDを成功数へ数えない。

## 7. ARC-AGI-3固有要求

- 経路：`接続/ARC3提出agent.py`→`接続/共通観測経路.py`→HDS照会→**行動選択・認可**→公式SDKへ1回だけ作用→応答再観測→記憶更新。
- 現行のHDS候補は`実行許可:False`。機械的にtrueへ変換してHDSの確定行動を偽装しない。**競技用の独立した探索・作用制御層**を構築し、合法な作用集合、実行予算、危険と停止条件、候補の根拠を明示する。確定行動と試行探索を分ける。
- 1作用と複数の応答frame、遅延効果、レベル完成、RESET/ゲームオーバー、失敗を対応付ける。game/level IDの固定行動列、hidden evaluatorの使用禁止。
- HOLD専用の`MAX_ACTIONS=1`を本番実能力として残さず、**少なくとも2回の非RESET合法作用を含む独立エピソードを複数試行**し、観測→行動→結果→次判断が繋がることを接続受入条件とする。これだけでゲーム攻略成功とは判定しない。
- `記憶/事前記憶/v0.4`、HDSの学習状態と既存解析は、合法で出所・公開境界が確認できた部分をKaggle環境へ同梱または正規提供し、実際に読込み・推論に反映されたことを検証する。同梱されていない資産を使用済みと主張しない。
- Phase AのNotebook COMPLETE／placeholderと、Phase Bの**Competition Rerunが実際にゲームを進めた結果**を厳密に区別する。

## 8. 日次運転契約

- 公式score取得後は「前回公式score→失敗署名→改善仮説→最小変更→同条件ローカル回帰→公式提出→同ID採点照会→台帳更新」を各競技で独立反復。
- **両大会とも原則1日1提出**。公式ルールで両方とも1日最大1件、最終審査への選択は最大2件。提出前に現時点の残枠・基準日・大会資格・期限を公式確認。提出上限回避や他アカウントの利用は禁止。
- Codex会話が永続すると仮定しない。Windowsタスクスケジューラ等**正規の常駐・定期起動手段**、追記型台帳、再開ファイル、送信重複防止を用意し、起動機構とセッション再開を実際にテスト。常時実行環境や認証が無ければ未成立と記録し、必要な権限・入力をOwnerへ具体的に示す。
- 一方のPENDINGで他方の修理・検証・提出を止めない。改善候補なしを同一内容の無意味な再提出で隠さず、原因の未解消を記録。
- 公式公表の最終提出期限は**2026-11-02 23:59 UTC／JST 11-03 08:59**（最新公式で再確認）。終了後は外部提出を停止し、最高得点の版・最終選択・証拠を凍結。初回受付や文書作成は停止条件でない。
