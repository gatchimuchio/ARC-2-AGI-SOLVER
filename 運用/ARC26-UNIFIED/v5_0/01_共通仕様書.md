## 1．目的

**既存の学習機械、公式サンプル、解析資産、事前記憶を実際に使って問題を解き、公式スコアを獲得・改善し、ARC Prize 2026で勝利を目指す。**

提出そのもの、Notebookの起動、テストのPASS、資料の整備は目的ではない。これらは実際に解くための手段である。

Codexの仕事は次の一本の循環を成立させること。

**学習機械を動かす → サンプルと解析資産を使う → 問題を解く → 結果を採点する → 失敗原因を直す → 同じ条件で再実行する → 得点を上げる。**

## 2．既にあるものを使う

両リポジトリの現行AGENTS.md、コード、検証結果を確認した上で、以下の既存基盤を再利用する。

| 役割 | 両リポジトリの既存配置 |
| --- | --- |
| 学習機械 | HDS/学習系統/v0.4.2 |
| 公式サンプル・入力 | 入力/ |
| 解析済み知識・事前記憶 | 記憶/事前記憶/v0.4 |
| 現行の設定・状態 | 制御/現在状態.json |
| 既存の接続、提出、評価、テスト | 接続/、道具/、検証/、運用/ など |

既存機械が使えないと判明した機能だけ最小限修復する。資産があるのに読み込まない、新しい空の機械で置き換える、既存解析を無視してゼロから実装することは、原因を説明できない限り禁止する。

## 3．ARC2の実行仕様

1. 現行学習機械に、許可されたtrainingの入出力例と既存の構造化記憶を与える。
2. その結果から、評価対象のtest入力に対する出力格子を推論する。評価対象の正解は推論側へ渡さない。
3. Kaggle仕様に従い、全testへattempt_1、attempt_2を生成する。二つの合理的な候補がある場合は別案を使う。
4. 実際に正解した格子数・割合、HOLD・誤答・候補衝突を測る。入力格子の単純コピーや二候補の無意味な複製を正解・改善に数えない。
5. 正解できない問題の失敗箇所を調べ、学習、記憶参照、機構推論、候補選択を必要な範囲で修正する。
6. 同じ評価条件で改修前後を比較し、正答能力が上がった版をKaggle提出経路へ接続する。

**現状の既知問題：** 提出用の資産梱包が事前記憶を利用しておらず、過去の実行記録では259出力中258件がHOLD由来のfallback。さらに二候補が同一になっている。この実行経路を最初の修正対象とする。

## 4．ARC3の実行仕様

1. 現行学習機械に、公開ゲームの観測例、解析済みの機構・作用知識、事前記憶を使わせる。
2. 公式SDKでゲームを観測し、可能な作用を推論して実行する。
3. 実行後の画面・状態・報酬を観測し、次の作用を選び直す。終了状態または正当な資源・環境制約に達するまで循環する。
4. 到達レベル、ゲームの完了、作用数、得点を測る。人間基準に対する作用効率も評価する。
5. 進まない原因を機構推定、観測、作用選択、学習更新、時間・作用予算から特定し、修正する。
6. 同じ条件で再実行し、実際にゲームをより良く攻略する版を公式提出へ接続する。

**現状の既知問題：** 提出agentはほぼRESET後にHOLDして終了し、提出bundleは事前記憶を除外している。これを「攻略agent」として合格させない。

## 5．再現性は各実行の当然の品質条件

毎回、使用した**コード版、学習機械、記憶、入力サンプル、評価条件、出力・操作履歴、測定結果**を対応付けて保存する。

- 同じ条件で再実行し、同じ結果になるか、違うならどこから変化したかを確認する。
- 過去の局所成功と今回の別データの得点を同じ測定値として比較しない。
- 歴代の実行環境を復元できない場合は未確認と記録し、現行資産から再現できる基準線を作って開発を続ける。
- 再現検査を別の巨大な承認工程にしたり、資料回収が終わるまで実行を止めたりしない。

HDSの判断HOLDは、直ちにプログラム全体のSTOPを意味しない。ARC2は別候補の検討、ARC3は許可された観測・試行を続けられる。ただし根拠のない推論をHDS確定解と偽ったり、候補生成器が無審査で自己承認したりしない。

## 6．合格条件

以下を、**実行した結果**で判定する。

- ARC2：既存学習機械が解答を生成し、検証用の正解が分かる課題で実際の正解数が計測されている。
- ARC3：既存学習機械が合法な作用を出し、ゲームが実際に進み、到達と効率が計測されている。
- 両方：同じ入力・条件で改修前後を比較でき、得点を阻害する失敗に対して原因と修正結果が示されている。
- Kaggle：提出された実装版と公式の確定スコアが対応付いている。

これらは中間検収である。**非零得点、初回提出、局所テストPASSで競技目標を完了にしない。** 公式スコアを継続的に改善し、勝利を目指す。

## 7．保持条件

- 両リポジトリのAGENTS.md、保護された現在状態、既存成功資産、Git履歴を尊重する。
- ARC2のtask ID別解答表、ARC3のgame ID別固定操作列、評価正解・非公開情報の混入は禁止。一般化できる構造・機構を使う。
- Kaggleの現行ルール・提出枠・権限を守る。必要な権限がなければ具体的に報告する。
- 既存データの削除、関係のない大規模改修、失敗版の履歴隠蔽は禁止。
- ローカルの実行成功、競技能力、公式スコアを区別して報告する。
