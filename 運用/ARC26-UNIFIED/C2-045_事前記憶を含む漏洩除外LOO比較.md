# ARC26-UNIFIED C2-045：事前記憶を含む漏洩除外LOO比較

## 根拠・目的

- 正本: ARC26 共通3点セットv3.0。ARC2公式 `57576155` は `COMPLETE/public_score 0.00`。P5では258 fallbackを正答として扱わず、公開training同条件評価を要求。
- P5候補LOO群は `prior_examples_used=0` だが、公式 challenge runtime は承認済みtraining prior 2例を読んでいる（`P5_runtime_stage_full-20261024T1045Z.json`）。現在のP5比較はこのproduction条件を反映しない。
- 目的は解法採否ではなく、承認済み事前記憶の有無だけを変えた比較により、P5 LOOの実験条件を公式runtimeへ近づけること。

## 許可範囲

- 公開 `training` split と正本 `接続/ARC2/テンプレート充填教材.json` のみ利用。`接続/ARC2/HDS接続.py` の `事前教材を読む()` を使用し、memoryの出所がtrainingであることを検証。
- 同一の現行HDS source、task、test input、LOO foldに対し、previous=`事前教材=[]` / current=`承認済み2 prior例` を比較。source、HDS、solver runtimeは変更しない。
- 事前memoryのsource task、およびtrain入力がmemory入力と一致するtaskは、prior-memory漏洩を防ぐため両条件から丸ごと除外。識別子・格子・答えは結果へ保存しない。識別子照合はevaluation-only leakage guardであり、solverへ渡さない。
- LOOのheldout outputはsolverから隔離し、solver返却後の親評価器のみが採点。fallback/input-copyを正答として数えない。hidden/evaluation splitは読まない。
- 変更先は新規 `運用/証拠/ARC26-UNIFIED/` 配下の分析script・匿名aggregate・run recordとwork ledger追記だけ。production code/提出/Notebook/Kaggle操作は禁止。

## 受入条件

1. previous/currentが同じeligible fold集合で実行され、training manifest・HDS source・test inputが一致する。
2. memory overlap exclusionが実行され、source task数・除外task/fold数だけ記録し、task ID/gridは出力しない。
3. exact first answers、distinct second candidate exact/wrong、union exact、fallback数、runtimeのprevious/current/deltaを示す。fallbackは採点正答に含めない。
4. solverがheldout outputを受け取らないこと、hidden/evaluation solutions未読、task IDs/grids未保存を機械確認。
5. memory効果が確認されない限り、production候補は変更しない。結果をappend-only work ledgerへ保存。
