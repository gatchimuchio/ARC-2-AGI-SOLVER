## 0. 最上位目的・責任

1. **主語はラーニングマシン。最上位目的は、そのラーニングマシンを実際に使ってARC Prize 2026 ARC-AGI-2で入賞すること。** 既存ソルバー、公式教材、事前記憶、外部モデル、リポジトリデータ、Codexは、その目的を実現する手段である。
2. **本件は同時に「学習の定義」の実証実験である。** 同じ学習機械が、経験を記憶し、推論・採否・適応を更新して、次の未知入力に対する候補・判断・実出力を変えることを反証可能に検証する。Kaggle入賞と学習定義実証を別々の代替目標に分けない。どちらか一方のみなら部分成果である。
3. 実装担当のCodexは、失敗原因を自分で特定し、**Learning Machine v0.4.2の実装コアも必要なら改修・再設計する**。個別の関数変更や改変可否をOwnerに逐一聞かない。ただしHDS原理正本・秘密Native、保護されたリポジトリ権限規範を独断で変更・公開しない。
4. 改善を主張する必要条件は**同一条件のprevious/current/deltaと採点分母**。未成立の試作や効果0の実装は実績へ昇格しない。競技の提出物の成立は、Kaggleの終端ステータスと数値score、版・source hash・submission IDの照合で判定する。

## 2. 競技契約（公式仕様を固定）

- 2026-10-29確認のKaggle公式表示では、最終提出期限**2026-11-02 23:59 UTC＝11-03 08:59 JST**。実際の最終操作前に再確認する。
- コードコンペで**Notebook提出、CPU/GPUとも最大12時間、インターネット無効、出力は`submission.json`**。L4×4の提供記述はあるがアカウントの利用可否・quotaは実測する。
- 各test入力に`attempt_1`と`attempt_2`を提出する。どちらかが正解格子と完全一致すればそのtest出力が正答。採点分母は**test出力の個数**であり、task数ではない。
- 公式ルールには**1日最大1 Submission、最終選択最大2**とある。ERRORやscore nullから枠の扱いを推測せず、公式履歴・残枠・API拒否を照会する。正常な0.00は採点済みでありエラー扱いしない。
- 賞の資格には公開ソース・方法・成果物に関する義務がある。HDS秘密中核の非公開原則とは別の制約。公開可能な解法で競技を戦い、秘密実装を使用したwinning submissionの公開義務が衝突する場合だけOwnerに明確な選択肢と根拠を提示する。**非公開Notebook＝公開義務の免除ではない**。

## 3. 実得点を生むアーキテクチャ

**意思決定と学習の主体は、各課題の外側から内側まで一貫したHDSラーニングマシンである。** 以下の観測、候補生成器の選択、採否、探索予算、反例更新、次課題への一般記憶の継承をLearning Machineが管理する。外部ソルバーの単独実行は比較基準であり本件の完成形ではない。

`公開train入出力 + test入力 + 許可された一般事前知識`
→ `Learning Machineの観測・記憶・仮説状態`
→ `Learning Machineが選んだ生成部品群（既存資産／公開モデル／プログラム帰納）`
→ `train実行照合・反例抽出・推論更新・再生成`
→ `Learning Machineによる候補採否・追加探索・予算・暫定Action Gate`
→ `相補的2予測 → Notebook本番・公式数値score`
→ `実測結果を用いた次の一般記憶・推論手続きの更新`。

### 3.1 候補生成の三本柱

1. **強い外部生成部品**：Kaggleで現に稼働した公開モデル／Notebook、公開重み、合法な推論コードを調査し、ライセンス・open-source義務・評価データ混入・依存・CPU/GPU/RAM・12h・無ネット動作を受入検査。部品単体での得点は**能力上限と比較用の基準測定**として確保し、学習機械に候補・確信度・費用・失敗情報を返す形で組み込む。外部解法をそのまま提出するだけで最終目的達成としない。
2. **汎用プログラム帰納**：格子全体・物体・色役割・包含・接触・方向・D4・クロップ・平行移動・拡縮・反復・マスク・塗分け・パネル関係・条件分岐を、型付き演算と少数演算合成で仮説化。公開train全例を実行して不一致を局所化し、反例から変数・制約・演算順を再生成する。単にfamily名を増やさない。
3. **既存Learning Machine／旧成功資産**：`HDS/学習系統/v0.4.2`、`記憶/事前記憶/v0.4`を学習・判断の主体として用い、既存ソルバーの汎用演算・失敗署名を接続する。旧120/167の問題専用答えやID依存分岐は使わない。機械が次課題で部品選択・仮説・予算を変えることを最小実働要件とする。

生成した候補は`generator, version, model/program SHA, train_fit, LOO, counterexample, test_grid, uncertainty, cost, validity, HDS_verdict, action_origin`を保持する。学習モデルの直接予測と、train完全再現したプログラムは異なる証拠型として保持する。

### 3.2 HDS Learning Machineの改造境界

- `v0.4.2`は**変更可能なソフトウェア基底**。課題またぎ保持、候補の生成・表現、採否、反証による降格、失敗記憶、探索予算、出力を変えるために必要なら、**学習系統の実装コアを修正・分割・置換してよい**。修正には同じ入力での単体・統合・回帰・因果差分を必須とする。
- HDS Frameworkの「未確定」とARC2の「二つの暫定回答を出す」は別状態。`HOLD`は真理主張の保留であって、合法な候補を全て棄却しinputコピーへ落とす指令ではない。暫定Action Gateは候補の根拠とリスクを記録して二試行を発行する。
- **記憶保持の必要条件**：課題ごとに新しいHDS個体を作る場合も、課題横断で許可する一般原理・優先順位・失敗署名は明示的なstateで再利用する。task ID、hash、正解格子をキーとする記憶・再生は禁止。学習時の正解は公開trainだけ。
- **HDSの効果を反証可能に**：同一候補集合に対してHDS ON/OFFで候補選択・探索量・出力・スコアが変わるかを測る。更新の有無で未来の判断が変化しなければ、HDSの「学習成立」は主張しない。
- **変更不可領域**：Ownerが保護する`AGENTS.md`、`制御/現在状態.json`、神域原理・HDS理論／秘密Nativeの正本・非公開運用ログ。これらの書換えや公開は今の実装裁量に含めない。実装コア改変と理論正本改変を混同しない。

### 3.3 二試行・実行時間

- `attempt_1`は最も高い推定正答確率の合法な格子、`attempt_2`は**追加の正解を拾う期待値が最大の異格子**。出力同一時は複製の寄与0と明記する。
- 予測が失敗した時は`candidate_missing`／`invalid`／`train_conflict`／`HDS_rejected`／`timeout`／`fallback_identity`を別署名にし、最多の真因から修正する。無根拠なidentityコピーは形式救済であり解答実績ではない。
- 全件の合法出力を早期確保後、未処理の入力に必要な計算を守りながら、期待増分の高い課題へ探索時間を配分する。終了時のファイル書出しと停止猶予を確保し、12時間を使い切らない。

## 4. 評価・学習・採否の厳密契約

1. **漏洩防止**：公開trainingの開発集合と固定holdoutを事前分割、実行入力にはtrain入出力・test入力のみ。評価正解ファイルは採点側の別プロセス／別ディレクトリからのみ読む。`arc-agi_evaluation_solutions.json`を提出runnerへ同梱しない。hidden正解、旧答え表、task ID分岐、testの正解への人手後追い適合を禁止。
2. **外部モデル用holdout**：既存100件にはVARCのARC1 trainingとのID重複が36件あり、未見と断言できない。既存の固定集合は履歴として残し、**既知重複と入力等価を除外する追加事前登録コホート**を作る。モデルの実際の事前学習範囲が不明なら`exposure_unknown`として報告する。
3. **局所採点**：`pass@1`、`pass@2`、`unique_attempt2_hits`、`fallback`、`HOLD`、`candidate_coverage`、`time_out`、`wall`を分母つきで計算。モデルごとにGPU・seed・予算・依存・入力版を固定し`previous/current/delta`を保存する。
4. **学習A/B/C/D**：A＝生成器のみ、B＝HDS判断・探索制御あり/記憶なし、C＝汎用事前記憶あり/オンライン更新停止、D＝同じ事前記憶あり/オンライン更新有効。採点器・候補生成器・seed・計算上限・対象を固定し、A→B／B→C／C→Dの選択・出力・正答・記憶更新の差を測る。Cの照会が状態を変えるなら固定記憶をコピー／snapshotで実現し直す。
5. **採用**：追加holdoutのネット正答と再現性が増え、重大な回帰がない版だけ性能改善版へ。得点不変・悪化版は実装研究として隔離し、mainや公式提出へ無批判に昇格しない。評価セット反復適合と同一データ汚染は成果に数えない。
6. **公式確認**：`submission_id + kernel slug/version + source/asset SHA + terminal status + errorDetails + numeric publicScore`を一致確認。`0.00`は公式採点成立だが競技力の不成立。`PENDING`、`score=null`、`private run COMPLETE`を成功にしない。
7. **主語の検査**：外部部品のみの基準scoreと、同一部品を使いLearning Machineが観測・記憶・推論・採否・適応したscoreを分ける。後者のruntimeにLearning Machineの実選択トレースがあり、ON/OFFと更新ON/OFFの反事実比較が成立して初めて「Learning Machineを使った結果」と帰属する。**モデル搭載、HDS import、ログ増加、外部スコアの借用は不可**。

## 5. 受入条件と勝利への優先順位

| Gate | PASSの実証 | 不成立の場合 |
|---|---|---|
| G0 現況 | 最新HEADと公式score・残枠・データhash一致 | 未観測と明記して再照会、能力開発は継続 |
| G1 生成能力 | Learning Machineが部品を呼び分けて未知入力候補を生成し、既存より追加holdoutの`pass@2`純増 | 生成部品・学習機械の推論接口を取り替え、診断ループを打切る |
| G2 HDS因果 | HDS判断・更新が将来の探索／出力を変え、その未見効果を測れた | コア・Adapter・記憶を再設計。`import`と更新回数は成果扱いしない |
| G3 公式増分 | 自己ベスト`0.83`超えをまず実公式scoreで確定、さらに上位へ | 競争力未達。次の最大ボトルネックへ |
| G4 入賞 | Kaggle公式順位と賞資格で成立を判定 | ローカル代理指標から入賞と称さない |

**優先順位**：①Learning Machineを実際の推論・選択・記憶更新の主体として稼働 → ②合法で強い生成部品とプログラム帰納を配下に接続 → ③反例更新・二試行相補性・計算配分で実正答を増やす → ④コアを含むA/B/C/Dの因果改善 → ⑤得点改善版の公式提出。得点のために外部部品を採用する裁量はあるが、**Learning Machineを外した別製品へ置換する裁量ではない**。
