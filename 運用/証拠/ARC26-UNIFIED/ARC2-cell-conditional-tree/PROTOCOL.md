# 同形状セル条件木・隔離実験

この実験は現在trainから入力セル特徴の一部を選ぶ条件木を学習する。本番・凍結bundle・Kaggle Notebook・事前記憶には組み込まない。公開能力改善、公式スコア改善、HDS中核の木発見能力は未実証である。

## 重複確認と再利用

`接続/ARC2/局所近傍変換候補.py` の `LocalCellContextCandidate` は同じ問い合わせ形状の教師の3×3文脈を完全キーとして出力色を集計する。未知・矛盾文脈のセルは入力色を保持する。文脈の一部だけで分岐を学ぶ木ではない。同モジュールの `_context` と `_shape` を変更せず再利用する。

`接続/ARC2/既存物体特徴.py::dominant_background_for_grid` も再利用する。最大頻度色が複数ある場合は、この実験では背景役割を未確定とし、既存関数の先頭出現による同率決着を使わない。

`接続/` と現行HDS v0.4.2を検索し、別担当の独立読取監査でも、同等のセル決定木学習器や「局所文脈補完」の実装は見つからなかった。HDSの決定的対応候補は観測値間の関係推論であり、セル木の発見器ではない。既存の特徴近傍変換は格子全体の単純変換選択である。

## 有限文法

同形状とは各教師対の入力と出力の形状が同じことを指す。異なる教師や問い合わせの縦横サイズを同一値に固定しない。すべてARCの1〜30×1〜30、色0〜9を検査する。現在trainの不正・形状変更対は黙って除外せずHOLD。同一入力の異なるtargetはHOLD。同じ観測を繰り返しても独立教師支持数を増やさない。

入力のみから33のカテゴリ特徴を作る。

- 既存3×3文脈の9色（盤外は-1）。
- 周囲8セルと中心色の一致・不一致・盤外。
- 3×3各セルの背景・前景・盤外・背景未確定の役割。
- 上下左右の境界フラグ。絶対row/column、正規化座標、行列番号を特徴にしない。
- 四近傍の中心同色数・前景数と、入力palette数。

枝は一つの特徴カテゴリを検査する多分岐である。未観測カテゴリの枝を補間しない。葉の型付きプログラムは、中心色、周囲8色、唯一の最大頻度色、唯一の最少頻度色の11入力役割、または学習した定数色0〜9。盤外や同率で未定義の役割を必要としたらHOLDとなる。

固定の辞書式費用は `(実現する木の総node数, 定数葉数, 入力役割費用和)`。中心コピーの役割費用は0、近傍・背景は1、唯一最少色は2。定数色は入力役割より後に置く。この役割優先は本実験の明示的な帰納バイアスであり、公開成績から調整した値ではない。同じ最小費用の木・葉プログラムはすべて残す。

## 探索・支持・棄権

既定上限は深さ3、各実現木15nodes、教師8件、合計学習4096cells、各葉に異なる教師入力2件かつ2cells、再帰fit状態256、各部分問題の同率候補32、計測work 2,000,000単位である。workは葉の教師支持走査・プログラム適合のセル検査・特徴分割走査に計上する。有限33特徴・21葉プログラムも固定されている。上限は「返せた先頭候補を採用する」ために使わず、不完全探索は全体HOLDとする。

2,000,000workはfit計測の上限であり、問い合わせ・全教師再実行を含む総runtime上限ではない。共有された下位forestを問い合わせ時に複数回評価する場合があり、深さ・候補数による有限性だけで短時間完了は保証しない。公開ハーネスの90秒worker上限を保持し、timeoutを失敗として全分母へ計上する。

各部分問題で、全セルを説明する葉があれば最小葉を返す。そうでなければ、まずすべての1段分岐を調べる。子も分岐する木は最低5nodesなので、網羅した3〜4node解はnode費用の大域最小である。必要な場合だけ深い木を探索する。これにより浅い規則を探す前に深い不適合候補で予算を消費する初期欠陥を修正した。

全最小木を直積展開せず、各部分問題の選言forestと各枝の下位forestを保存する。各下位forestは同じ最小費用を持つ。問い合わせ時には全選択肢が同じ色を計算する必要があり、どれかの未知カテゴリ・未定義役割・出力不一致で格子全体をHOLDにする。未処理セルだけ入力色で埋める継続は行わない。

採用候補forestを現在trainの全入力格子に再適用し、全target格子との一致を確認する。学習後のモデル状態には型付き木、葉プログラム、カテゴリ、支持数、上限・探索統計だけを保持する。raw teacher/target格子、問題ID、filename/hash、answer mapを状態に入れない。学習用の教師番号は支持数集計だけに用い、runtime分岐に残さない。

## APIとHDSの境界

```python
model = CellConditionalTree(current_train)  # default full 33-feature grammar
prediction, diagnostic = model.候補(query_input, {})
state = model.model_state()
loaded = CellConditionalTree.from_state(state)

machine = new_hds_machine()
admission = model.admit_to_hds(machine, current_train)
result = model.query_via_hds(machine, query_input)
```

schemaは `arc2-cell-conditional-tree-v1`。`FEATURES`、`Bounds`、`HDS_BOUNDARY` も公開する。生格子や余分な欄を状態へ追加すること、支持不足の葉、型・複雑度不整合は読込で拒否する。

木発見はこの外部モジュールが行う。`admit_to_hds` は変更していない既存 `候補機構を学習` を通し、`query_via_hds` は既存 `出力格子(..., 同値必須=True)` を使う。候補器HOLDでは `hds_queried=False`、HDSがHOLDなら直接候補に差し替えない。既定HDSの最小支持3を変更しない。2教師で外部木が全train再現しても同値採用されず、3教師での採用と反例拒否を合成試験で確認した。

既定 `_connection()` は本モジュール位置から作業treeのHDSを解決する。凍結snapshotで公開比較するハーネスは、凍結済みHDSへの接続を明示的にbindするか、呼出後まで実際のimport元・source hashを検査する必要がある。snapshot外のHDSを混ぜた結果を同条件と扱わない。

## 実行済み合成検証

```powershell
& '.venv/Scripts/python.exe' -m pytest -q '運用/証拠/ARC26-UNIFIED/ARC2-cell-conditional-tree/test_cell_conditional_tree.py'
```

結果: **14 passed in 5.32s**（tool chunk `1f1e68`）。

- 既定33特徴から中心背景の分岐を誘導し、未見色・未見3×3文脈の前景再彩色を計算。既存の完全文脈写像は同じ問い合わせを正答できなかった。構成した合成例の比較である。
- 左端では中心、他では左隣色を使う型付き木を誘導し、別形状・別色の格子へ計算で適用。
- 重複支持・矛盾・不正対・形状変更・各葉の異なる教師支持不足・未知カテゴリ・同率役割の不一致・各種上限・教師順序不変・状態読込・fresh process計算を検査。
- 実HDSの既定支持ゲート、採用・問い合わせ、反例拒否、HDSのHOLD非迂回を確認。

学習の合成例では、A3とA+F4で同じ上限・特徴文法（上下左境界のうちtopとleft）・未見Uを使用し、両時点ですでに異なる教師支持2件/葉とHDS支持3件を満たす。Aの内側ではnorth色とwest色が一致するため両役割が残り、非対称UはHOLDだった。Uとは異なる非対称Fを追加すると役割の曖昧性が除去され、同じUが既存HDS経由で正答になった。before/afterとも同値採用true、全4教師を再検証。Uのtargetはfitへ渡さず最後の採点assertだけで使用した。

この合成例の未見格子正答previous/current/deltaは0→1 / +1。beforeは候補器が曖昧でHDS照会まで進まず、afterは実HDS照会で回答した。これは同一Pythonプロセス内で別の外部木と別HDSインスタンスを再fitした証拠であり、HDS中核が木を発見した証拠や、HDS記憶の永続化・公開能力改善ではない。fresh process試験は型付き外部状態の読込・計算を別に検証する。

## 公開評価への条件

公開ハーネスは別担当がこの新ディレクトリ内に作る。固定20課題、元train最低5件からU/Fを除いたA最低3件、両時点とも既定の全33特徴、同じU/F、同じHDS・制限で比較する。baselineは既存 `LocalCellContextCandidate`。直接候補とHDS経由を分け、全課題分母の正答・誤答・HOLD・timeout、退行、previous/current/delta、時間、構造変化を記録する。

この作成担当は公開の重い実行・Kaggle・台帳変更を行っていない。公開改善がなければ本番採用しない。固定した外部木の学習・HDS採用という境界も維持する。
