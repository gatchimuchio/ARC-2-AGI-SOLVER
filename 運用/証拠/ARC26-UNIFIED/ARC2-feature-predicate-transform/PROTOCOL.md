# 入力特徴述語による単純変換誘導・隔離実験

本ディレクトリは公開データ比較前の実験である。本番の候補機構、凍結bundle、Kaggle Notebook、事前記憶には組み込んでいない。合成例で機構とHDS接続が動作することを確認した段階で、公開問題の能力改善、公式スコア改善、HDS中核の新しい発見能力を主張しない。

## 既存機構との差分と再利用

- `接続/ARC2/特徴近傍変換選択.py::_feature` の入力のみから得る25特徴をそのまま用いる。既存の特徴近傍選択は単一教師からの変換候補と距離で選択する。ここでは現在の複数教師から特徴述語を誘導する。
- `接続/ARC2/単純変換候補.py::fitted_models/apply_model` をそのまま用いる。変換文法は既存のD4向き、plain/crop/scale/downscale/tile、整合する色写像である。新しい格子変換実装を複製しない。
- 既存の `特徴条件整列.py` は囲みマーカーによる物体残差移動を扱う。本実験は入力格子の一般特徴による二つの型付き単純変換の選択であり、その物体機構を置き換えない。
- 調査した既存コードに、この一般特徴一述語と二つの `fitted_models` プログラムを現在教師全件で誘導・検証する同等機構は見つからなかった。単一の全教師共通変換で説明できる場合、本実験は `global_transform_already_supported` でHOLDとし、既存の単純変換機構との重複採用を避ける。

## 有限文法と学習手順

1. 現在教師の入力・出力の全件を検査する。不正教師を黙って除外しない。同一入力で異なる出力があればHOLDとする。同一の観測の重複は枝支持数を増やさない。
2. 全教師共通の既存単純変換があるか調べる。なければ入力特徴ごとの観測値の隣接区間を分岐候補とする。左枝と右枝のそれぞれに異なる入力を最低2件必要とする。
3. 各枝の全教師に `fitted_models` を適用し、最も単純な型付きプログラムをすべて残す。教師部分集合が同一なら再利用する。
4. 述語と左右プログラムの組を比較し、同じ最小複雑度の仮説をすべて保持する。順序による代表仮説の恣意的な選択をしない。
5. 採用候補の各仮説を、現在の重複除去済み教師全件に再適用し、一件でも異なればHOLDとする。ここで用いる正解は現在のtrain教師だけである。

プログラムの辞書式複雑度は `(操作数, 幾何種別費用, 拡縮因子積-1, 色変更数)`。操作数は非plain幾何を1、非identity向きを1、色変更ごとに2とする。幾何種別費用はplain=0、crop=1、scale/downscale=2、tile=3。仮説は左右の費用和に述語操作1を加える。これは性能で調整した重みではなく、この隔離実験の固定された単純性規則である。

既定探索上限は、教師8件・述語128件・異なる分割32件・枝ごとの同率最小プログラム16件・同率最小仮説256件。いずれかを超えたら全体をHOLDとし、先頭候補への打ち切りで答えを選ばない。枝支持の最低2件は下げられない。入力は既存 `valid_grid` の制約に従う。

## 推論と棄権

述語は入力特徴番号、左枝最大観測値、右枝最小観測値、表示用の中点閾値で表す。未観測区間内はどの閾値でも教師を説明できるため、問い合わせ特徴がこの区間に入ればHOLDとする。区間外も全仮説の出力一致が必要である。型付き変換が適用できない、色変更に未観測入力色が入る、同率最小仮説の出力が一致しない場合もHOLDとする。

`候補(grid, context)` はcontextの正解・問題IDなどを使用しない。予測は入力特徴と型付きプログラムを計算して得る。学習後に教師格子を保持せず、入力格子やtarget格子によるruntime検索を行わない。

## 状態とAPI

`feature_predicate_transform.py` は以下を提供する。

```python
candidate = FeaturePredicateTransform(current_train)
grid_or_none, diagnostic = candidate.候補(query_input, {})
state = candidate.model_state()
reloaded = FeaturePredicateTransform.from_state(state)

machine = new_hds_machine()
admission = candidate.admit_to_hds(machine, current_train)
result = candidate.query_via_hds(machine, query_input)
```

状態schemaは `arc2-feature-predicate-transform-v1`。保存対象は探索上限、使用特徴番号、観測数・再検証数、固定文法の述語・左右プログラム・枝支持数、複雑度、探索統計のみ。プログラムはorientation、幾何種別・因子・背景色、色写像パラメータであり、生の入力・target格子、問題ID、filename、hash、answer mapを含めない。fresh processでのJSON読込と未見入力の同じ計算出力を合成試験で確認した。保存状態は外部発見器の状態であり、HDS記憶の保存・復元を実証したものではない。

## HDSの境界

述語とプログラムの発見はこの外部実験モジュールが行う。HDSは現行 `接続/ARC2/HDS接続.py` のままである。

- `admit_to_hds` は既存 `候補機構を学習` を呼び、現在教師に対する候補と教師出力の同値関係をHDSへ観測させる。戻り値の `採用可` / `同値採用` / 反例をそのまま証拠に残す。
- `query_via_hds` は候補が得られた場合だけ既存 `観測へ` と `出力格子(..., 同値必須=True)` を呼ぶ。HDSがHOLDなら候補を代わりに回答しない。戻り値に元のHDS結果と `hds_queried` を残す。
- 候補器HOLDは `hds_queried=False` と区別する。直接生成の正答数と、実際のHDS経由回答の正答数を別に評価する。

合成試験では既存のHDSによる採用・問い合わせと、追加反例に対する不採用を実行した。これはHDS経路を通った事実であって、HDS中核がこの述語を発見した証拠ではない。

## 公開比較への移行条件

公開比較は別担当の `public_harness.py` / `PUBLIC_HARNESS_PROTOCOL.md` が定義する。両方の時点で同じ最低支持・上限を満たすAとA+Fを固定し、同じ未見U、同じHDS条件、同じ時間上限で比較する。Fの正解はA+Fの学習時だけ与え、Uの正解は採点側だけに置く。対象群・分割・seedを成績を見る前に固定する。

previous/current/delta、正答・誤答・HOLD・timeout、退行、実時間、候補直接出力とHDS経由出力、仮説構造変化を残す。公開比較の正の差と退行を確認するまで本番へ採用しない。公式スコアとは別の証拠として扱う。
