# ローカル開発環境

## 目的と範囲

現在の正本は`制御/現在状態.json`、学習機械は`HDS/学習系統/v0.4.2`。
Windowsの`.venv`で編集・Notebook・工具の試験・Kaggle操作を行う。
資源制限付きのARC2評価はWSL Ubuntuで実行する。
WindowsはPython 3.12系、WSL評価環境は既存実行契約と同じPython 3.12.14を使用する。

## 構築

Python 3.12とGitが必要。リポジトリのルートで実行する。
Windowsでは`python3`がStoreのエイリアスになる場合があるため、`python`を使用する。

```powershell
$env:PYTHONUTF8 = "1"
python --version
python -m pip install --user uv==0.12.19
git submodule update --init --recursive
python -m uv sync --locked
python -m uv run --locked python -m ipykernel install --sys-prefix --name arc2 --display-name "ARC2 (Python 3.12)"
python -m uv run --locked python 道具/リポジトリ環境監査.py
python -m uv run --locked python 道具/開発環境確認.py
```

`uv sync --locked`は`uv.lock`からプロジェクト専用の`.venv`を構築する。
NumPy 2.3.5・SciPy 1.17.0は`requirements-runtime.txt`と同じ値に固定する。
学習機械はeditable依存として導入するため、Notebookからも`hds学習系統`をimportできる。
OneDriveのハードリンク制約に合わせ、uvの`link-mode`は`copy`に固定する。
既存の別プロジェクトの仮想環境を有効化している場合は解除してから実行する。
依存を追加・更新する際だけ`pyproject.toml`と`uv.lock`を合わせて更新する。
通常実行では`--locked`により意図しないバージョン変更を検出する。
[uv公式仕様](https://docs.astral.sh/uv/concepts/projects/sync/)

| 道具 | 用途 |
| --- | --- |
| NumPy・SciPy・Matplotlib | グリッド計算・整数計画・描画 |
| HDS学習系統 | 現行ソースを直接参照する学習機械 |
| JupyterLab・ipykernel | Notebookによる入力観察・実験 |
| pytest・Ruff | ローカル試験・静的検査 |
| Kaggle CLI | 認証後の大会データ取得・Kaggle接続 |

追加のPyTorch・CUDA等は推論方式と実行先に応じて導入する。
仮想環境や生成物はGit管理対象外。OneDrive配下では`.venv`も同期対象になり得るため、
同期負荷が問題になった場合はチェックアウト全体をOneDrive外へ移し、環境を再構築する。

## 日常の実行

```powershell
$env:PYTHONUTF8 = "1"

# 構造契約とローカル実行環境
python -m uv run --locked python 道具/リポジトリ環境監査.py
python -m uv run --locked python 道具/開発環境確認.py

# 環境・Kaggle接続工具の検査と試験
python -m uv run --locked ruff check .
python -m uv run --locked pytest -q

# Notebook画面を起動。カーネルは ARC2 (Python 3.12) を選ぶ
python -m uv run --locked jupyter lab
```

仮想環境のActivateやPowerShellの実行ポリシー変更は不要。
`PYTHONUTF8`はこのPowerShellセッションの日本語ログをUTF-8に統一する。
エディターでPythonを選択するときは`.venv/Scripts/python.exe`を指定する。
Jupyterカーネルの登録先もこの`.venv`内に限定する。

Ruffの既定対象は環境・Kaggle工具とそのtestsに明示する。
最新mainにはhash固定の過去資料・回帰scriptがあるため、一括整形で証拠を変更しない。
ソルバー本体は関連回帰と、次の正規評価入口で検証する。

## WSLの正規評価環境

Windowsの`resource`非対応を避け、CPU・メモリ・wall上限を維持してLinuxで実行する。
WSL Ubuntu-24.04を用意した後、PowerShell 7で次を実行する。

```powershell
pwsh -NoProfile -File 道具/WSL環境構築.ps1
pwsh -NoProfile -File 道具/WSL評価.ps1 -OutputPath 出力/WSL評価/current.json
```

構築先はLinuxユーザーホームの`.local/share/arc2-wsl/`。
Windowsの`.venv`と別の環境を使用し、入力・ソース・出力は同じ作業フォルダを参照する。
`-OutputPath`は既存ファイルを上書きしない。
個別入力の実行は`-InputPath input-only.json`を指定する。
入力JSONには`train`とtestの`input`だけを渡し、課題IDやtest正解を含めない。
CPU10秒・address space512MiB・wall60秒の制約と
`OPENBLAS_NUM_THREADS=1`を維持する。詳細は[`RUNTIME.md`](../RUNTIME.md)を参照。

環境の起動成功と、全120題の解答性能を同一視しない。
評価結果には実行OS・Python・依存版・資源失敗を残す。

## 入力資産

`入力/公式ソース/ARC-AGI-2`は既存のsubmodule契約に従い、
commit `f3283f727488ad98fe575ea6a5ac981e4a188e49`へ固定する。
`data/training`に1,000題、`data/evaluation`に120題の公開JSONがある。
公開JSONは問題ごとのファイルであり、Kaggleの集約済み6ファイルとは別形式である。
公開evaluationの正解を調整に用いた場合は、未見評価として扱わない。

`道具/開発環境確認.py`は全公開JSONの形状・値域と環境を検査する。
これはソルバーの解答精度やKaggleでの受理を証明する試験ではない。

## Kaggle接続

大会ページでログイン・参加・規約同意を行った後、Kaggle CLIを認証する。
規約同意と本人の認証操作はユーザーが行う。
[公式CLI認証手順](https://github.com/Kaggle/kaggle-cli/blob/main/docs/README.md)

```powershell
python -m uv run --locked kaggle auth login
python -m uv run --locked kaggle competitions download arc-prize-2026-arc-agi-2 -p 入力/Kaggle
python -m uv run --locked python -m zipfile -e 入力/Kaggle/arc-prize-2026-arc-agi-2.zip 入力/Kaggle
python -m uv run --locked python 道具/開発環境確認.py
```

APIトークンを使う場合はユーザーホームの`.kaggle/access_token`へ保存する。
認証情報をこのリポジトリやチャットへ記載しない。
配布物の保存先`入力/Kaggle/`はGit管理対象外。
CLI 2.2.4の大会downloadは`--unzip`に対応しないため、ZIPを別途展開する。
取得後は既存の`入力/公式サンプル/マニフェスト.json`に対して照合する。
不一致があれば配布更新または取得状態を調べ、マニフェストを自動変更しない。

## 大会実行との境界

2026-09-29に公式大会ページで確認した条件:

- Kaggle Notebook提出。CPU・GPUとも実行時間12時間以内、インターネット無効。
- 大会専用L4×4（合計96GB VRAM）が利用可能。通常GPUの2倍のクォータを消費する。
- 出力は`submission.json`。各test入力に`attempt_1`と`attempt_2`を用意する。
- 公開`arc-agi_test_challenges.json`はplaceholderであり、採点時は未公開データへ差し替わる。

[公式実行条件](https://www.kaggle.com/competitions/arc-prize-2026-arc-agi-2/overview/code-requirements)・
[公式データ説明](https://www.kaggle.com/competitions/arc-prize-2026-arc-agi-2/data)

KaggleのPython・CUDA・ライブラリの実バージョンは、Notebookを実際に起動して確認する必要がある。
このローカルlockfileはKaggleとの互換性確認や、オフライン提出用wheelの準備を代替しない。
