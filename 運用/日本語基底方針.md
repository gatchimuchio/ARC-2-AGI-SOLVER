# 日本語基底方針

## 原則

実務上やむを得ない場合を除き、repository内部の基底言語は日本語とする。

日本語を正本とする対象:

- 設計文書
- HDSの観測、Frame、目的、問い、判断理由
- HDSコンパイラの中間表現と診断
- ミニドラの命令形、仮説、推論、計画、出力候補
- 記憶の事実、定石、因果、適用条件、反例、失敗
- 内部schema名、Failure Signature、log、test意図
- strategy、roadmap、instruction

## 英語を許す境界

次は外部接続のため必要な場合に限り原文を保持できる。

- Python等の予約語・標準構文
- package / moduleの外部固定名
- ARC / Kaggle SDK、API、schema、action名
- 公式配布ファイル名
- GitHub Actions等の外部仕様で固定されたkey

これは英語を思考基底として採用することを意味しない。

## 二重正本の禁止

英語版を内部正本として作り、日本語訳を従属させる運用は禁止する。内部では日本語を正本とし、外部Adapterで必要な記号へ射影する。

## コード

識別子を日本語にでき、可読性・toolchain・外部互換性を損なわない場合は日本語を優先する。外部interfaceに接続する識別子は固定名を維持し、境界を明示する。
